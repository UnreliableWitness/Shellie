# Brain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local, git-backed "brain" folder per Azure DevOps project that Shellie feeds (dropped files, pasted text, a mirror of a chosen wiki subtree), maintains through headless Claude Code skills, shows in a screen and a task tab, and hands to every task of that project through `task.md` and `--add-dir`.

**Architecture:** New main-process module `src/main/brain/` (store, templates, converters, source pipeline, wiki mirror, state file, job runner, IPC handler group, scheduler) wired into `Services` like `createDocsHandlers`. Ledger gets a fourth `Attribution` level `brain`; brain usage arrives through the existing OTel receiver tagged `shellie.task.id=brain:<id>`. Renderer gets a `brain` screen, a Brain tab and a Brains settings category, reusing the docs markdown viewer.

**Tech Stack:** Electron, React, TypeScript, Vitest, zod, `yaml` (present); new pure-JS deps `pdfjs-dist`, `mammoth`, `jszip`. Claude Code CLI headless (`-p --output-format json`).

**Spec:** `docs/superpowers/specs/2026-11-03-brain-design.md`

## Global Constraints

- Everything runs through Claude Code on the owner's subscription; no API key, no cloud routines, no Claude Code hooks.
- Brain cost records: `attribution.level === 'brain'`, `billable: false`, never returned by `LedgerStore.dirty()`.
- The PAT never appears on a command line or on disk: git auth goes through `extraHeaderEnv` (`src/main/services/gitAuth.ts:53`) as `GIT_CONFIG_*` env.
- `SCHEMA.md` is the schema file; no `CLAUDE.md` is ever written into a brain.
- `sources/` is never edited by the agent: the brain's `.claude/settings.json` denies `Edit`/`Write` under `sources/`.
- Headless job flags: `-p --output-format json --model <brain.options.model> --permission-mode acceptEdits --strict-mcp-config`; sessions kept (no `--no-session-persistence`); `CLAUDE_CODE_DISABLE_CLAUDE_MDS` unset.
- Context section in `task.md`: heading `## Context: <brain name>`, then `The project's brain is at <path>. Read-only for this task: read pages, do not edit them.`, then at most 150 lines of `index.md`, then `… N more in index.md` when cut.
- Log line at task close: `- <ISO timestamp> task #<work item id> closed: <title> (<PR url or branch>)`.
- Daily token cap default 500000; the cap stops jobs from starting, never kills one.
- Stale lock: older than 3600 s, or its pid is not alive.
- Brain names, paths, source names and content never go to telemetry; events listed in `docs/telemetry.md`.
- Windows is the release target: no native modules, paths through `path`, commands through `Platform`.
- Lint/format: `npm run lint` (oxlint + oxfmt); run `npm run lint:fix` before each commit.
- Each task: `npx vitest run <file>` for its tests; `npm run typecheck` before each commit.

## Review Focus

1. A dropped file whose name has no extension, or an unknown extension (`.xyz`): the inbox row says "unsupported" and nothing is written to `sources/` (Task 5 test `rejects an unsupported extension`).
2. A VTT transcript with overlapping cues and `<v Speaker>` voice tags: speaker labels survive, no cue text is lost or duplicated (Task 3 test `keeps voice tags and merges consecutive cues`).
3. A wiki refresh after a page was deleted in Azure DevOps: the mirror file disappears and the commit says so; a page renamed is a delete plus an add (Task 7 test `removes mirror files for deleted pages`).
4. A headless job whose process prints shell profile noise before the JSON, or exits non-zero: the job is marked failed with the last stderr line, the lock is released, the queue continues (Task 8 tests `releases the lock when the job fails` and `parses the last JSON line`).
5. Two tasks of the same project finishing at the same minute: both log lines land in `log.md` and the second commit does not fail on the first (Task 12 test `appends two close lines in a row`).
