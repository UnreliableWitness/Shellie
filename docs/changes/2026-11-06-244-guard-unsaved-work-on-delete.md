# Finish and Discard no longer delete unsaved work without a confirm

Finish (with "Remove worktree folder" or "Delete local branch") and Discard task now refuse to remove a worktree folder that holds uncommitted files, or to delete a branch that holds commits no remote has, unless the developer confirmed it (issue #244, 2026-11-06, `agent/issues/244-add-guards-against-deleting-a-local-bran`). Before, both always ran `git worktree remove --force` and `git branch -D`, so that work was gone.

How main decides, in `src/main/ipc/handlers.ts` (`lostWork`, from the per-workspace `discardCheck` that Discard already used for #124): a removed folder loses its changed and untracked files (`git status`, ignored files do not count); a deleted branch loses its commits since the task's base that no remote ref contains (`git rev-list <branch> --not --remotes <base>`). A branch pushed to any remote, or merged into a branch that is, loses nothing; a branch without commits of its own loses nothing. A repo without a remote has nothing anywhere else, so every commit since the base counts. Only what a cleanup actually removes counts: keeping the branch keeps its commits, keeping the folder keeps its files, a workspace on another branch is never touched. When Finish creates the pull request (or pushes a workspace), the branch goes to origin first, so only the folder's files count. Dropped workspaces keep their own check. A check that cannot run (git failing) counts nothing, as before.

The check runs before anything happens (no push, no PR, no closed terminals): the error names what would be lost ("Nothing was removed, since that would lose 1 uncommitted file and 2 commits on no remote.", with the repo names for a task with several repos), and the task stays ready. The override is `confirmDiscardUnsaved` on `FinishOptions` and a second argument to `tasks:discard`. The Finish page sends it when it showed the loss and its "Discard changes and clean up" button was clicked; when main finds work the page did not show (Claude worked since it loaded), the page shows the refusal and the same danger button confirms it. The Discard bar sends it from "Discard anyway", and after a refusal it loads its checks again so that button appears. The background retry of a held folder (#115) is unchanged: it only runs after the developer chose to delete.

The spec suggested a new `GitClient.unsavedWork` built on Finish's `pushState`; the existing `discardCheck` already counts exactly this, per workspace and also for a folder removed by hand, so Finish and Discard now judge the same numbers the Discard bar shows. Telemetry is unchanged.

Not verified: on Windows, and in the app itself (handler tests with real git repos, renderer tests with a fake api). Not in this change: recovering lost commits from the reflog, branches or folders deleted outside Shellie, and treating a squash-merged PR as pushed (only presence on a remote counts).
