# Agentic SDLC stage 3

Agentic SDLC stage 3 (plan `docs/superpowers/plans/2026-10-26-agentic-sdlc-stage-3.md`) implemented 2026-10-26 on `UnreliableWitness/agentic-sdlc-stage-3`: `agents-pr.yml` runs review → decide → fix → publish-fix. `decide` (`tools/agents/pr.mjs`, rules in `pr-decide.mjs`, no LLM) first does bookkeeping for issues with `agent:pr-open` (PR merged → `agent:merged` with `mergeSha`; closed unmerged → `agent:needs-owner`), then per bot `agent-pr` PR: waits for CI (`test (macos-latest)`, `test (windows-latest)`, `windows-installer`, latest run per name) and the review of the head; fixes red CI, critical/important review findings (the reviewer now stores them as `items` in the PR's status block), new trusted PR comments (by time, `lastSeenAt`) or a conflict (`dirty`, even before CI); `update-branch` when behind; merges (squash, `sha` pinned, one per poll) only in `full` mode when green, reviewed `approve`, `main`'s last CI green, no hold/stop, and either a low-risk bug/chore ≤400 lines without owner-only files or the owner's Approve on that SHA; otherwise `agent:awaits-owner` with one comment per SHA; after `maxFixRounds` (3) `agent:hold-merge` + `agent:needs-owner`. The fix job (macOS, Claude token only, Sonnet, `sdlc-fix` skill, `runAgentJob` shared with the implementer, `origin/main` merged in for a conflict) and `publish-fix` (fast-forward only: the bundle must build on the PR head, no force push; protected paths over `origin/main...branch`) mirror the implementer's split. `agents-notify.yml` (`notify.mjs`, no LLM, every 30 min) comments "Fixed in vX.Y.Z …" on `agent:merged` issues once a published release contains the merge (`compare`), labels `agent:released` and closes; no release 90 min after the merge → one comment and `agent:needs-owner`. Triage reopens a released issue closed in the last 30 days on a new trusted comment ("still broken", seen-mark written first) and classifies an open `released` issue as reopened. Fixes from the first live run (#132 → PR #138): the jobs' own files live in `$RUNNER_TEMP/agents` (`AGENTS_WORK`; `task.json` in the checkout failed `npm run lint`), failing check output (last 60 lines) is shown folded in the PR, the attribution line appears once, and owner-only paths now include `package-lock.json`, `.claude/**`, `scripts/**`, `.npmrc`, `.mcp.json`, vite/vitest configs and `CLAUDE.md` unless lines are only added. Review fixes: agent text can no longer forge a status block (only a block at the very end of a body counts, `renderStatus` defangs its summary, comments, PR bodies and reviews with agent text go through `defang`); bookkeeping finds merged PRs whose issue GitHub already closed (`listIssuesByLabel`, state all); "behind main" comes from `compare(main, head).behind_by` (GitHub reports `behind` only under strict protection), and a branch is updated only when it could otherwise merge; the owner's latest review decides (Request changes blocks merging, its text goes to the fixer); each PR is handled in its own try/catch; the fix bundle counts first-parent commits (a merged busy main no longer looks like 60 commits); the fixer's skill and schema are read from main's checkout before the branch is checked out; a fix on an unchanged head waits an hour; the merged branch is deleted; main's CI is the newest push run that was not cancelled and counts as not green while it runs; taking `agent:hold-merge` off resets the rounds. Known gaps: not run live yet; any new trusted comment on a released issue reopens it (spec 5.1 wanted the agent to judge "still broken"; the triage run that follows does); review threads are not checked for resolution (the owner's Request changes and comments cover it); the two flaky tests that turned CI red on 2026-10-26 are quieted: `ChangesTab.test.tsx` "shows another file when clicked" gets a 15 s test timeout (its two 5 s waits outran vitest's default 5 s), and `costServer.integration.test.ts` runs only with `SHELLIE_COST_SERVER_IT=1` (the cost server does not exist yet; the CostSender and ledger unit tests still run). Node-project tests get 60 s on Windows (20 s elsewhere): the multi-repo Finish tests in the handlers tests (`src/main/ipc/handlers.part*.test.ts`) run real git and timed out at 20 s on the Windows runner.
