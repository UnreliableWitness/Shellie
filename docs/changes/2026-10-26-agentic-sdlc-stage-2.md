# Agentic SDLC stage 2

Agentic SDLC stage 2 (plan `docs/superpowers/plans/2026-10-26-agentic-sdlc-stage-2.md`) implemented 2026-10-26 on `UnreliableWitness/agentic-sdlc-stage-2`, live in `AGENTS_MODE=implement` (nothing merges by itself): the implement poller (`.github/workflows/agents-implement.yml`, `tools/agents/implement.mjs`) runs as three jobs so the agent, which runs code, never shares a machine with the App token: `pick` (ubuntu, App token) takes the oldest `agent:ready` issue (bugs, chores, features; one agent PR open at a time, 2 attempts, an hour after a failure, a 3-hour-old lock released) and adds `claude-working`; `implement` (macOS, Claude token only) runs Claude Code Opus with the `sdlc-implement` skill (`--restricted`, Bash limited to npm checks and local git) on `agent/issues/<n>-<slug>` from the `main` commit pick saw, runs `npm test`, typecheck and lint itself and uploads a git bundle; `publish` (ubuntu, App token, fresh machine) checks the bundle (one head, base ancestor, 1-50 commits), refuses the hard-denied paths (`classifyPaths` in `publish-checks.mjs`), marks owner-only paths, >400 changed lines or failed checks as `risk:high` with an "Agent checks" list, pushes and opens the PR (`Fixes #n`), or releases the lock (`agent:needs-owner` after the last attempt or when the agent is blocked; a usage limit gives the attempt back). The PR poller (`agents-pr.yml`, `review.mjs`) reviews each new head SHA of a bot `agent-pr` PR once with the `sdlc-review` skill (Opus, read-only, `--restricted`, in a worktree of the PR head), posts a `COMMENT` review with findings on lines (body-only on a 422), keeps the verdict in the PR's status block and can raise `risk:high`. Each poller keeps its own block on the Agent activity issue (`activityStore.mjs`; triage in the body, others in a comment) and the cap and pause read them together. Review fixes: changed paths come from `git diff -z` (git quotes unusual names otherwise, which slipped past the path check), a denied path goes to the owner at once, the push sends the token as an extra header through git's environment and a failed push releases the lock, publish writes the PR's status block with its issue and turns closing keywords in the agent's text into `refs #n`, a failed review is retried after an hour and given up on for a commit after two failures, an attempt is given back for a usage limit at most twice, a stale lock at the last attempt goes to the owner; `agent:go` is one-shot (removed when acted on; on an untrusted reporter's issue it becomes `agent:approved`; on `needs-owner` it resets the attempts); the App token reaches the triage and review scripts in a file they read and delete at start (`readTokenFile`), never in the environment. Known gaps: not run in Actions yet; closing an agent PR without merging leaves `agent:pr-open` (stage 3); before `full` mode the protected paths need `.claude/**` (settings hooks, new skills), `CLAUDE.md`, `.npmrc`, `.mcp.json` and `vite.*.config.mts` (owner-only at least); the reviewer's allowed `git diff`/`git log` accept `--output=<file>` (writes on the runner, which holds no token in its environment or on disk); no fixer, merge or release notice yet (stage 3); the implement job's own check results are reported by the agent's machine and only advisory (CI on the PR is the gate).
