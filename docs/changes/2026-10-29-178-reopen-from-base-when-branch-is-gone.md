# Reopen makes a lost branch again from its base

Reopen on a Done task no longer fails with "Branch … cannot be restored: it was deleted and is not on origin" (issue #178, 2026-10-29, `agent/issues/178-reopening-a-task-doesnt-work`). That happened when Finish had deleted an unpushed branch and there was no usable last commit to bring it back from, for example for a task finished before Shellie recorded summaries. `restoreSource` in `src/main/ipc/handlers.ts` still tries the local branch, `origin/<branch>` and the summary's last commit first; after that it now always falls back to the workspace's base (`baseSha`, else `baseRef`, whichever still exists), where before it did so only when the summary said the branch had no commits. The branch is created again under its old name, so the task is back as it was when it started. Any unpushed work on the lost branch is not recovered. Only when the base is gone too does Reopen still refuse, now with "… cannot be restored: it was deleted, is not on origin, and its base is gone too", and the task stays Done. Telemetry is unchanged: `task.reopened` already reports `from: 'base'`.

Not verified: on Windows, and in the app itself (only through the handler tests with real git repos). Not in this change: recovering lost commits from the reflog, telling the user in the UI that the branch was made again without its old commits, and keeping unpushed branches at Finish.
