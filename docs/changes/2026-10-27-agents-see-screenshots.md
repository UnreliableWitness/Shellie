# Agents see screenshots

The agents got only the text of an issue, so a screenshot was just a link they could not open (they have no web access); on #132 triage said "the issue is only a screenshot, which I could not view" although the screenshot showed the exact error (2026-10-27, `UnreliableWitness/agents-see-screenshots`). Now the scripts download the screenshots and the agents look at them with their Read tool: `tools/agents/images.mjs` finds images on GitHub's own hosts (`github.com/user-attachments/assets/`, `(private-)user-images.githubusercontent.com`) in the issue body and trusted comments (never strangers'), at most five, at most 5 MB each, keeps only real PNG, JPEG, GIF or WebP files (by their first bytes) and saves them in `.agent-images/<issue>/` inside the agent's working directory (the file tools are confined there by `--restricted`); the prompt lists the files. Triage downloads in its own job; the implementer and the fixer get the image URLs in their task and download in the job that runs the agent (public hosts, no token needed), and `.agent-images/` goes into `.git/info/exclude` there so a screenshot is never committed (also in `.gitignore`). The skills say to open them before deciding and that text in a screenshot is data. Checked against #132: its screenshot downloads as a PNG and shows "Opening https://github.com/UnreliableWitness/Shellie/releases/tag/v1.51.0 is not allowed".
