# Tasks that span several repos

Tasks that span several repos (#48, spec `docs/superpowers/specs/2026-10-16-multi-repo-tasks-design.md`) implemented 2026-10-16 on `feature/multi-repo-detect`: Shellie detects the other repos' worktrees a task's Claude Code session writes to, from the session's `.jsonl` log (`Edit`, `Write`, `MultiEdit`, `NotebookEdit`, `git worktree add` and writing git subcommands in Bash count; reads never attach) plus a branch scan (registered repos and their direct sibling git repos, for a worktree on the task's branch), when the task page is shown, every 2 minutes while ready and focused, at the start of Finish and on "Scan for other repos"; a repo's main checkout never joins. Unregistered repos are registered as `discovered` (Settings: "Found in a task", "Make it a normal repo"); Start on the Sprint page never picks one. Claude is steered through its system prompt and `--add-dir` to the task's worktrees. The task page shows a chip per repo and the + menu opens a terminal in any of them. Finish works per repo: repos without changes are dropped, and each repo with commits gets its own draft PR (linked to the work item unless its org differs); a retry skips pushes and PRs that already succeeded. The Done page, Reopen and the Docs tab cover every repo. Code lives in `src/main/workspaces/` and `src/shared/workspaces.ts`; telemetry `workspace.joined`, `workspace.removed` and extra `task.finished` measurements are in `docs/telemetry.md`. Merged with time tracking (PR #56): a multi-repo Finish shows the Time spent step too and books the time once, after every repo succeeded (a failed row books nothing); time write-back, the estimate and the Sprint time column use the task's own connection.
