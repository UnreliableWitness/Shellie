# Agentic SDLC stage 1

Agentic SDLC stage 1 (spec `docs/superpowers/specs/2026-10-26-agentic-sdlc-design.md`, plan `docs/superpowers/plans/2026-10-26-agentic-sdlc-stage-1.md`, owner guide `docs/agents.md`) implemented 2026-10-26 on `UnreliableWitness/agentic-sdlc-github-issues`: a triage poller (`.github/workflows/agents-triage.yml`, every 15 min) runs Claude Code headless on the owner's subscription (`CLAUDE_CODE_OAUTH_TOKEN`; the scripts refuse to run with `ANTHROPIC_API_KEY`, never `--bare`) with the `sdlc-triage` skill and `--json-schema`, and either asks the reporter 1-3 questions or posts a fix spec (problem, cause with file:line, change, test, docs) in a status comment it edits in place (hidden `<!-- shellie-agent {...} -->` block, trusted only from the bot), with `agent:*`, `kind:*`, `risk:*` labels. The orchestrator in `tools/agents/` decides and acts; the agent gets no GitHub token (`agentEnv`) and only text by logins in `.github/agents/trusted.yml` (others' issues wait for the owner's `agent:go`). Issues assigned to someone, with an `issues/<n>-` branch or a PR naming `#n` not by the bot are left alone. Limits in `.github/agents/config.yml` (5 issues per run, 20 agent runs a day, max turns); a usage-limit error pauses all agents for an hour; the "Agent activity" issue (label `agent:activity`) holds the pause, run counts and shadow memory. `AGENTS_MODE` (`off`/unset, `shadow`, `triage`, later `implement`, `full`) is the kill switch. Issue forms in `.github/ISSUE_TEMPLATE/` (blank issues stay on), CODEOWNERS for the agents' own rules. `node tools/agents/triage.mjs --dry-run <n>` triages one issue locally and writes nothing (on #132 it found the `shell:openExternal` allowlist refusing the GitHub releases link). Known gaps: not run in Actions yet (needs the owner's GitHub App, token and `AGENTS_MODE`); stages 2-5 (implementer, reviewer, fixer, merge, notifier, Report a problem, health, gardener) are not built; "still broken" on released issues waits for stage 3.
