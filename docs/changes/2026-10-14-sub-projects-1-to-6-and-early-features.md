Sub-project 1 (app shell and task lifecycle) merged 2026-10-14 (PR #1). Sub-project 2 (Azure DevOps connections and work item picker) merged 2026-10-14 (PR #2). Sub-project 3 (AI usage capture, pricing and work item write-back) merged 2026-10-14 (PR #3). Sub-project 4 (official prices only) merged 2026-10-14 (PR #4). Sub-project 5 (Windows support) merged 2026-10-14 (PR #5): Windows `Platform` (PowerShell 7 or 5.1), CI on macOS + Windows (`.github/workflows/ci.yml`) building `Shellie-Setup.exe` as a run artifact, Azure Artifact Signing that switches on when the six repo/environment variables exist (owner setup steps in `docs/superpowers/specs/2026-10-14-windows-support-design.md`). Sub-project 6 (sci-fi UX, splash, icon and art) implemented 2026-10-14 on `UnreliableWitness/ux-design-art-splash`: Culture/Instrument look with bundled fonts, compact task strip and collapsible nav, per-task Usage tab, Focus mode, animated splash with real boot steps (setting `showSplash`), Mind dial icon (`.icns`, `.ico`), Gemini art logged in `assets/ART.md`, an explicit app menu (macOS without Actual Size, so Cmd+0 opens the Usage tab; no menu bar in packaged Windows builds). The ADO redesign (issues #9 #10 #11 #12 #15, spec `docs/superpowers/specs/2026-10-15-ado-redesign-design.md`) implemented 2026-10-15 on `issues/ado-redesign` replaces sub-project 6's look: Azure DevOps dark palette, Segoe UI, Fluent icons (`@fluentui/react-icons`), a 40px header with breadcrumb, a 240px left nav with a project switcher and an aligned Done section (#11), every screen as a full page with no overlays (#15), and a short ADO-style splash; the Gemini art is off the screens (#12). The app opens on the Sprint page (#9): the current sprint of the project's default team in ADO backlog order with parent/child nesting, a filter box (ID, title or assignee, keeping the parents of a match, #43), the Shellie task status per row (a click on it opens the task; a click anywhere else on the row, or on the title, opens the work item in Azure DevOps, #30) and a primary-blue Start to create the task straight away with the repo's `.shellie.yml` defaults and open its setup (#24; New task stays for changing options). Real work item type icons and state colors come from the project (`workItems:types`, fetched in main, cached per connection, sent as data URLs). Finishing a task records a git summary (commits, diff stat, pushed) before the worktree goes, and the Done page (#10) shows duration, changes, commits, cost split, time write-back and the live ADO state. Review fixes: task branches are made with `--no-track`; the summary starts at the task's recorded `baseSha` (merge base for older tasks, commits marked unavailable when neither resolves) and counts the branch as pushed when `origin/<branch>` contains HEAD; the iteration work items API was verified live to follow the backlog (StackRank) order; running tasks' terminals stay mounted (hidden) across pages. Work item state and draft PRs (spec `docs/superpowers/specs/2026-10-15-workitem-state-and-pr-design.md`) implemented 2026-10-15 on `feature/workitem-state-pr`: task setup has an "Update work item" step that moves the work item to its type's first In Progress state and assigns it to the connection's user (a failure is a warning, not a failed setup); Settings has per-repo start options (move, assign, a state per work item type). Finish has an optional "Create a draft pull request into <base>" (unticked on first use, then the last choice per repo): it pushes the branch, creates a draft Azure Repos PR linked to the work item with the commits in its description (or links an existing active PR), opens it in the browser, then cleans up; a failed push or PR stops before cleanup with Retry and Finish without PR. The Done page shows the PR with its live status. Finished tasks can be reopened (#44): Finish keeps the closed tabs in `closedTerminals`, and Reopen on the Done page either goes straight back to ready (worktree kept) or remakes the worktree through the setup pipeline (`reopen.from`: the local branch, else `origin/<branch>`, else the last commit of the Finish summary, else the base when the branch had no commits) with its copies and setup commands, then restores the tabs (Claude resumes its session; for older tasks the folder's latest session continues when Claude has one). Cancelling a failed reopen puts the task back to Done. The PAT now needs Work Items (Read & write) and Code (Read & write); existing tokens with Code (read) must be replaced to create PRs. Verified live against the test org on 2026-10-15. Docs tab, terminal links and Send to (spec `docs/superpowers/specs/2026-10-16-docs-viewer-design.md`) implemented 2026-10-16 on `feature/docs-viewer`: a Docs pivot renders the worktree's Markdown (GFM, highlighted code, Mermaid, Source view) and reloads on change; `path:line` and URL text in terminals is clickable; a `.html`/`.htm` path (in a worktree, or an absolute path to an existing file anywhere else, #80) opens in a tab of the task after the terminal tabs: main serves the file's folder on the privileged `shellie-view:` scheme under a random token (`src/main/htmlView.ts`; only the file itself when that folder is a filesystem root or the home folder), shown in a sandboxed iframe (scripts, no same-origin) with Reload and Open in browser (the app's CSP allows `frame-src shellie-view:` only), links that open a new window go to the browser, and the tabs are not kept across a relaunch; known gaps: a plain web link clicked inside the page is blocked by that CSP (Reload brings the page back), and the page cannot `fetch` files next to it or load module scripts from files (the scheme is not CORS-enabled), so only self-contained pages and classic scripts, CSS and images work; Send to pastes a quoted selection into a task terminal without Enter. The + in the task's tab row opens a menu of terminal types (Claude Code, the platform shell, Copilot CLI, OpenCode, whose requests are costed from its database; `NewTerminalMenu`), and every terminal tab has a close button (middle click closes too) (#38). The app icon is a faceted clam since 2026-10-21 (after a ship, PR #42, and the Gemini conch of 2026-10-18; history in `assets/ART.md`): hinge up, tilted 12°, four growth bands from near-white at the hinge to a navy rim. Four vector sources in `assets/icon/`: `shellie.svg` (Windows, 48 px and up, the clam alone filling the square, no tile, like other Windows icons) and `shellie-small.svg` (16-32 px, fewer facets, nearly to the edge); `shellie-mac.svg` (macOS, a pale blue `#dbeafb` tile at Apple's 824/1024 grid with a soft shadow) and `shellie-mac-small.svg` (no shadow, the clam larger). `npm run icons` renders each platform's full canvas: the PNGs and `.ico` from the Windows pair, the `.icns` from the macOS pair. `MindMark` shows the app icon itself (`assets/icon/png/64.png`) as a small decorative mark. Terminals use the system's own monospace font (Cascadia Mono, Consolas, SF Mono, Menlo), no bundled or preferred font (#25). Claude Code tabs start with the task in `--append-system-prompt` (`claudeContext`) and wait for the user's first message instead of starting work (#34); a Resume of a session the user never wrote in starts it again, since Claude only saves a session (`~/.claude/projects/*/<id>.jsonl`, `claudeSessions.ts`) after a message. Each Claude Code tab starts with its own `--session-id` (stored as `sessionId` on the terminal); its Resume session button (after an exit or an app relaunch or update) runs `claude --resume <id>`, or `claude --continue` for tabs from before this change (#28). After a relaunch, shell and Claude Code tabs start again by themselves when first shown (the shell fresh, Claude resumed); run and Copilot tabs keep the Restart button. One title bar since 2026-10-16 (#49, `fix/single-title-bar`): the system title bar is hidden and the 40px header drags the window (`titleBarOptions` in `src/main/windowChrome.ts`), with the macOS traffic lights inside its left end (no gap in full screen) and the Windows min/max/close drawn over its right end as a `titleBarOverlay` in the header's colours; in Focus the task's tab row takes that role. Terminals copy, cut and paste like VS Code's (#47, `terminalClipboard.ts`): Cmd+C/X/V on macOS (Ctrl+C stays SIGINT), on Windows Ctrl+C and Ctrl+X copy a selection and pass through without one, Ctrl+V and Ctrl+Shift+C/V copy and paste; before, xterm sent ^C/^V and packaged Windows builds have no Edit menu. Home (spec `docs/superpowers/specs/2026-10-17-home-dashboard-design.md`) implemented 2026-10-17 on `feature/home-dashboard`: the app opens on a cross-connection Home page (my open tasks with Up next and Start, PRs to review with team requests collapsed, my PRs, a card per current sprint with my items, and week/month stats from local data), backed by `HomeService` in main (`src/main/home/`), which fetches every connection in parallel with a 15 s budget each and caches the snapshot in `home.json`; a failing connection keeps its last data marked stale. Verified live against the test org on 2026-10-17 (sprint card, PR filters by reviewer, team and creator, a refused token turning the chip red with stale data kept); the live run also caught a rebuild loop on an expired token at launch (281 rebuilds in 20 s), fixed by rebuilding only when a connection is added or removed.
