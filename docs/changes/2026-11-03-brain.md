# A local second brain per Azure DevOps project, fed from files and wikis and handed to every task

Brain (spec `docs/superpowers/specs/2026-11-03-brain-design.md`, plan `docs/superpowers/plans/2026-11-03-brain.md`) implemented 2026-11-03 on `feature/brain`. A brain is one local git folder per Azure DevOps project (connection plus project) that Claude Code maintains as a wiki from raw sources, following the "second brain" method: `sources/` raw and never edited, `wiki/` written by the agent, `SCHEMA.md` (not `CLAUDE.md`, which Claude does not load from an `--add-dir` folder), `index.md`, an append-only `log.md` (newest first), `brain/state.json`, `brain/lock` and the four skills in `.claude/skills/`. It is local (no remote) and read-only towards Azure DevOps. The data lives in `brains.json` next to `state.json` (`BrainStore`, `src/main/brain/BrainStore.ts`; `Brain`, `BrainOptions` and the other types in `src/shared/brain.ts`); the folder defaults to `<userData>/brains/<id>`, or an existing folder with `SCHEMA.md` and the four skills is adopted. `scaffold.ts` writes the folder from the versioned `templates.ts` and makes the first commit; `brain:templateDiff` and `brain:updateTemplates` offer newer templates per file, never a silent overwrite.

Feeding. A file dropped on the Brain screen or a task's Brain tab, or pasted text, goes through `addSource` (`src/main/brain/sources.ts`) with no LLM: `convert/` turns PDF (`pdfjs-dist`, `## p.N`), DOCX (`mammoth`), PPTX (`## Slide N`, notes) and VTT (a heading per minute) into markdown, MD and TXT stay as they are. The result is `sources/YYYY-MM-DD-<slug>.md` with frontmatter (`source_url`, `ingested_at`, `content_type` of `sow`, `deck`, `doc`, `transcript`, `note`, `task`, `wiki-page`, `sha256`) and the original beside it; a duplicate hash is refused, a name clash gets `-2`; a PDF without a text layer is "needs OCR" and not captured. Shellie commits only the files it wrote (`git add -- <paths>`, `git commit -- <paths>`) and queues `/capture <file>`. The wiki mirror (`mirror.ts`, `wikiAccess.ts`) clones the chosen Azure DevOps wiki (project wiki or code wiki, both listed by `brain:wikis`; root page picked with `brain:wikiPages`) into `.mirror` with a sparse checkout, authenticating with the connection's PAT as an `http.extraheader` through `GIT_CONFIG_*` environment variables (the way `gitAuth.ts` does), then copies the pages under the root into `sources/wiki/` with frontmatter (page text with LF line ends, and the mirror's git calls run with `core.autocrlf=false`, so a page hashes the same on Windows), removes deleted pages and commits `sources/wiki/`. `.mirror` is only the clone; the skills and `SCHEMA.md` name `sources/wiki/` as the wiki copy. It refreshes on the button, once a day while the app is open (`scheduler.ts`; a failed one is retried after an hour), and at task start (8 s limit); a failed refresh never blocks a task.

Skills and jobs. `/capture <file>`, `/sync`, `/lint` and `/digest` are plain Claude Code skills in the brain folder that read `SCHEMA.md` first, so the brain works from any Claude Code. `/sync` diffs `sources/` (the wiki mirror included) and `wiki/` between `lastSyncCommit` and HEAD with git (the brain's `.claude/settings.json` allows `git diff`, `git log`, `git show`, `git rev-parse` and `git status`); `/lint`'s `uncaptured` finding is a source outside `sources/wiki/` that is not in `state.captured`. `BrainJobRunner` (`jobs.ts`) runs them headless: `claude -p "/capture <file>" --output-format json --model <haiku|sonnet|opus, default sonnet> --permission-mode acceptEdits --strict-mcp-config` in the brain folder (`brainJobFlags`; the brain's `.claude/settings.json` denies edits under `sources/`), sessions kept. One job per brain at a time (brains in parallel), oldest capture first, and every successful capture queues a lint at the front. `brain/lock` (pid and timestamp; stale after an hour or a dead pid, `state.ts`) is held per job; a held lock retries after 5 s. The job runs with `SHELLIE_TASK_ID=brain:<id>` and `SHELLIE_BRAIN_ID=<id>` (`brainJobEnv`) beside the telemetry variables. The daily token cap (default 500k, from the brain's ledger total of the day, `ledgerToday` in `health.ts`) stops jobs from starting, never kills a running one: the queue pauses (Health says so) and `brain:resumeQueue` continues it. The timeout is 10 minutes. Before the skill starts (lock held, the runner's `beforeJob`), Shellie commits whatever is dirty under `wiki`, `index.md`, `log.md` and `brain/state.json` as `Edited outside a capture`, so a job's commit never sweeps a person's edit in; that commit is not a `Brain:` one, so Health keeps listing its wiki files as edited outside a capture until a `/sync` (Health lists the wiki files of non-`Brain:` commits since the last `Brain: sync`, plus uncommitted ones, with `git --no-optional-locks status`). After a job's output, Shellie records a capture's source and session in `state.json` and commits wiki, index, log and state ("Brain: <kind> <source>"; only the paths of these that exist or are tracked, so an adopted brain without some of them still commits); a commit that throws fails the job. Every commit Shellie makes in a brain repo (sources, job output, outside edits, mirror, close line, scaffold, template update) goes through one in-process queue per brain folder (`withBrainGit`, `gitMutex.ts`), so two never race for git's index. A failed job is shown with its message and can be retried; the source stays. A paused job has no Retry: Resume on Health continues the queue. Optional per brain: `/sync` after a refresh that changed pages (`syncAfterRefresh`) and `/digest` on Monday, or the next time the app is open after a Monday it missed (`weeklyDigest`: enqueued when `lastDigestAt` is before the most recent Monday 00:00 local and nothing runs for the brain).

Cost. Usage of a brain is attributed to the brain, never to a task: `Attribution` has a fourth variant `{ level: 'brain', brainId, organization, project }` (`src/main/ledger/attribute.ts`), found by a `brain:<id>` task id (`brainTaskId`), which wins over everything, or, for a record no task claims by its id or Claude session, by the transcript's cwd being inside the brain folder (longest path wins, so headless jobs and a brain terminal are counted from transcripts by folder; a task worktree inside a brain folder stays the task's), and frozen like a task level. A brain record is never billable (`LedgerService.billableOf`, also for a brain that is deleted or not loaded yet) and `LedgerStore.dirty()` leaves it out, so the cost server never gets it and invoicing views skip it. A brain's usage is shown as today's tokens and EUR on its Health card only; the Usage screen does not list brains. A task's Claude reading brain pages through `--add-dir` stays the task's cost.

Brain-owned terminals. Every brain terminal is brain-owned: one interactive `claude` terminal per brain, stored on the brain (`Brain.terminal`), not in `Task.terminals` (`brainTerminal.ts`: `brainTerminalDef`, `brainClaudeArgs`, `createBrainTerminals`). It runs in the brain folder with `SHELLIE_TASK_ID=brain:<id>`, resumes its stored session (`--resume`) or the latest one (`--continue`), is shown in a task's tab bar from the "+" menu without belonging to the task, and survives Finish. "Continue in terminal" opens it on the job's session (a running terminal on another session is killed and respawned with `--resume <session>`, and the new session id is stored). Ask and "Resolve in terminal" pass their text to `brain:terminal(id, session, prompt)`: a new process gets it as Claude's first message (the positional prompt after the flags; `Platform.claudeCommand` has an optional `prompt`, quoted on macOS, an argument to `claude.exe` or an environment variable through an npm shim on Windows), a running one gets the text typed and, 50 ms later, `\r` to submit it. The Brain screen has Open terminal and, on the terminal panel, Close (kills it).

Task hooks. A work item reference now carries `project` (`WorkItemRef.project`, null for older tasks or typed by hand). The brain of a task is the one with the same connection and project (`brainForTask`, `context.ts`; the first when there are several); the project is `System.TeamProject` at setup, else the stored `workItem.project`, else the connection's project (older references only). A task without a work item gets no brain: no Context section, no `--add-dir`, no Brain tab, no close line (`setupBrain`, `taskBrain` in `handlers.ts`, `brain:forTask`). The setup plan gets a step "Brain context" (`SetupPlan.brain`, step id `brain`, shown on the New task summary and the Setup screen): it refreshes the mirror (8 s) and appends to `.shellie/task.md` (excluded from git) the section

```
## Context: <brain name>
The project's brain is at <path>. Read-only for this task: read pages, do not edit them.

<first 150 lines of index.md>

… N more in index.md      (only when cut)
```

when `contextInTaskMd` is on. With `addDirForClaude` on, the task's Claude terminal command gets `--add-dir <brain path>` (in `handlers.ts`, next to the other workspaces' folders). With `openBrainTerminalOnStart`, a task that is ready, has the brain and shows no brain terminal yet opens it (`brain:terminal`) into its tab bar without selecting it, once per task per app session (`brainTerminalOpenedOnStart` in `TerminalTabs.tsx`). At Finish (`brainAtFinish`, before the worktree goes; also on the finish paths of `handlers.ts`) the brain's `log.md` gets `- <ISO time> task #<id> closed: <title> (<PR link or branch>)` at the top of the entries, committed under the brain lock (`appendLog`; waits up to 30 s for a running job, then logs and skips); with the Finish option "Capture task.md into the brain" (`FinishOptions.captureTaskMd`, off by default) the file is first added as a `task` source named `<slug>-task.md`, without its `## Context:` section (`withoutContext`, so the brain never re-ingests its own index), and a capture queued. A brain that fails never fails the Finish.

Screens. The Brain screen (`BrainScreen.tsx`, `src/renderer/components/brain/`, one nav entry per brain under its connection): Inbox (drop zone, paste box, "Sources to capture" listing the uncaptured sources outside the wiki mirror from `brain:sources` with a Capture button each, then one row per job with its state, error, Retry for a failed one, the takeaways of a done one collapsed under "Takeaways", and Continue in terminal), Health (`health.ts`: last lint and findings with "Resolve in terminal", uncaptured sources, mirror pages and freshness, files edited outside a capture, queue paused by cap, tokens and EUR today), then Sources, Wiki and Log tabs, buttons Refresh wiki, Lint, Digest, Ask and Open terminal. Health is computed only by `brain:get` (git, a ledger scan, reading the sources); `brain:list`, `brain:forTask` and the other channels return `health: null`, so the nav, the task tab and Settings cost nothing. The task's Brain tab sits beside Docs and Changes for a task with a brain (`BrainTab.tsx`): `index.md` rendered at the top, a filter over the wiki pages' file names, the wiki list and viewer, and the whole tab as a drop target that adds files like the inbox (`useBrainDrop`); no cost. Settings › Brains (`BrainsSection.tsx`, user scope): per connection and project the brains with Create (name, project, folder, wiki and root page; the wiki picker is disabled until the typed project settles), the options (the four switches, token cap, model, brain terminal on start), Update skills, Open folder and Delete (asks whether to delete the folder; ledger records keep their attribution).

IPC (`src/shared/ipc.ts`): `brain:list`, `brain:get`, `brain:forTask`, `brain:create`, `brain:update`, `brain:delete`, `brain:pickFolder`, `brain:wikis`, `brain:wikiPages`, `brain:addFiles`, `brain:addText`, `brain:refresh`, `brain:run`, `brain:resumeQueue`, `brain:sources`, `brain:files`, `brain:read`, `brain:asset`, `brain:terminal` (brain, session, prompt), `brain:templateDiff`, `brain:updateTemplates`, `brain:openFolder`, and the event `brain:changed` (the renderer fetches `brain:get` again).

Telemetry: `brain.created`, `brain.source.added`, `brain.job`, `brain.refresh`, `brain.deleted`, `brain.screen.action`, `settings.brain`, the `brain` count in `ledger.records` and the screen `brain` are in `docs/telemetry.md`, with counts and kinds only. Brain names and folders go into the scrub list from the live store (`sensitiveValues({ brains })`, `src/main/telemetry/helpers.ts`, built in `src/main.ts`), so a brain created or renamed later is covered; source file names and content never leave the machine.

Known gaps: Windows untested (CI only; the converters are pure Node and git goes through `GitClient`); no OCR (scanned PDFs are listed as "needs OCR"), and images, deck pictures and wiki attachments are dropped; code wikis are mirrored only in tests, the wiki used live is a project wiki; the skills' quality was checked on fixtures only, not on real engagements; PDF conversion inside the real Vite bundle is checked by the packaged build's contents, not by converting a PDF in the packaged app; sharing, publishing back to Azure DevOps and work item attachments are not built (a brain is a git repo, `git remote add` is the way); the task's Claude can edit the brain through `--add-dir` (Health shows edits outside a capture until a `/sync`); the git queue per brain folder is in-process only (another process writing the brain is kept out by `brain/lock` for jobs and the close line, not for every commit); the Usage screen does not list brains (a brain's usage is today's tokens and EUR on Health); links inside the Brain tab's rendered `index.md` do not open the page; Copilot and OpenCode get the Context section but no skills; there is no picker in New task for several brains of one project (the first is used); source content is not scrubbed of personal data; the skills write their own timestamps into `log.md` and `state.json` and the live `/lint` wrote a made-up one (`09:00:00Z` for a run at 23:06 UTC), so the runner should hand the current time to the skills in a later change; the GUI flow (Brain screen, tab, settings) has not been exercised in a running app.
