# Onboarding

Onboarding (spec `docs/superpowers/specs/2026-10-22-onboarding-design.md`) implemented 2026-10-22 on `feature/onboarding`: a fresh install opens the Get started page (`get-started` screen, `GetStartedScreen.tsx`; a Home band lists the unfinished steps while `dismissedAt` is unset and a repo exists; Skip for now or the band's Dismiss hides it, and Settings › About › Get started clears `dismissedAt` and reopens the page) with three skippable steps, state in the `onboarding` setting (`dismissedAt`, `agentsCheckedAt`, `tracker`, `migrated`; the migration runs once per install, marked by `migrated`, and sets both timestamps only for installs that already have a repo when they first start this version). Agents: Settings › Agents and terminals detects Claude Code, Copilot CLI and OpenCode (`agents:detect`, `Platform.probeCommand`, telemetry booleans only) and pre-ticks the default terminals once. Connect: a page with a provider picker (GitHub shown as "Soon"), `Connection.provider` and `Connection.workItemOnStart` (copied into a repo's own options at `repos:add`, never retroactively), `connections:probe` to test a token and list projects, `connections:saveMany` for one connection per ticked project (named after the organization, the screens add the project; the same PAT); "Add a project" reuses the token. Add repository: a page (`repos:inspect` reads remote, lockfile, dotnet, dev script, apm, base branch; Shellie proposes a `.shellie.yml`; `repos:add` options choose to write it or keep the repo in Shellie only; the inspected base is kept on the repo and, without a file, is the base `repos:config` gives New task and Start; the proposal quotes the base and env file names). Work item handlers go through the `Tracker` interface in `src/main/trackers/` (Azure DevOps only; Home, UsageSync and `tasks:prStatus` still use `client()`). The Get started art (`assets/art/get-started.jpg`, prompt in `tools/art/prompts.md`, logged as pending in `assets/ART.md`) is not generated yet, so the page shows the app icon in its place; the prompt asks for 16:9 (the image tool has no 3:2) while the box is 3:2 with `object-fit: cover`, so the art will be cropped at the sides. Events and screens are in `docs/telemetry.md`. Verified live on macOS on 2026-10-22 on a fresh profile (`SHELLIE_USER_DATA`). Known gaps: verified on Windows by CI only; no GitHub implementation of `Tracker` (the picker says Soon); `.shellie.yml` stays on disk when registering fails after the write; the probe shows no token expiry; `agents:detect` caches its result, not the promise (two first calls probe twice).
