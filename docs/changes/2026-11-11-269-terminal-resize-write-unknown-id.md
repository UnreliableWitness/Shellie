# Resizing or typing into a dropped terminal no longer reports "Unknown terminal"

`terminals:resize` and `terminals:write` now return quietly for a terminal id main does not know, instead of throwing "Unknown terminal <id>" (issue #269, 2026-11-11, `agent/issues/269-terminals-resize-throws-unknown-terminal`). A terminal tab can outlive its terminal in main, after a relaunch for example, and its resize observer and keystrokes still call main for it. Each call threw in the IPC handler. The renderer did not catch it, so it was also reported as an unhandled rejection. Together these were the largest error source in Application Insights, although nothing was wrong for the user. The check sits in the handlers in `src/main/ipc/handlers.ts`. An ignored write does not fire `onTerminalInput`. `TerminalView` also catches failures of both calls now, so no other failure becomes an unhandled rejection. Gone-state handling stays with `terminals:buffer`. `TerminalManager.write` and `resize` still throw for unknown ids, because the internal callers (`src/main.ts`, `src/main/brain/brainTerminal.ts`) rely on that. This follows #180, which fixed only `buffer`. Telemetry events are unchanged.

Not verified: on Windows, and in the app itself (only through the unit and component tests). Not in this change: `kill` and the other terminal calls, filtering errors in the telemetry layer, and how terminals restart after a relaunch.
