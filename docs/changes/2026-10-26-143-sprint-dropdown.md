# Sprint dropdown on the Sprint page

The Sprint page header has a Sprint dropdown that lists every sprint of the project's default team, past, current and future, with the current ones marked "(current)" (issue #143, 2026-10-26, `agent/issues/143-add-dropdown-to-swap-between-sprints`). Before, the page only showed the first current sprint, so a user could not look at last sprint's or next sprint's backlog, or at a second sprint running at the same time. `AdoClient.iterations()` asks `teamsettings/iterations` without `$timeframe` and maps ADO's `attributes.timeFrame` to `timeframe` on `SprintIteration` (`currentIteration` shares the mapping, so it now carries `timeframe` too). `workItems:sprint` takes an optional iteration id and loads that sprint, and the new `workItems:iterations` channel returns the list. The dropdown shows only when the team has two or more sprints; the choice lasts while the page is open (switching projects resets it) and Refresh and window focus reload the chosen sprint. When the chosen sprint is gone from ADO, the page goes back to the current sprint. Without a current sprint the page still lists the work assigned to me until a sprint is picked.

Not verified: against a live Azure DevOps organization (only through the fake server in tests), and on Windows. Not in this change: picking a team other than the default one, remembering the choice across restarts, and the work item picker's sprint scope, which still uses the current sprint.
