# Secrets

Secrets (spec `docs/superpowers/specs/2026-10-23-secrets-design.md`, mockups `design/mockups/secrets/`) implemented 2026-10-23 on `feature/secrets`: Settings › Secrets is a per-scope manager (one repo or All repositories; a repo's own secret wins over an All one of the same name) with a column per environment (Development, Test, UAT, Production), masked values with hold-to-reveal (reveals logged locally), where each is given and a green/amber status panel (amber while a `copy:` file still holds a stored value, a stored value is committed in a tracked file, an open worktree still has an old plaintext copy, or git could not be checked). Values live in `<userData>/secrets.json`, encrypted with safeStorage and decrypted in main only (`src/main/secrets/SecretStore.ts`). Discovery (`discover.ts`, `sources/`) reads the repo's main checkout (root and two folders down: `.env*`, `appsettings.<Env>.json`, `Properties/launchSettings.json`, `.vscode/launch.json`, docker-compose, `local.settings.json`, `secrets/`, `*.secrets.json`) plus .NET user secrets (`Platform.userSecretsDir`), when the import page opens and once on Add repository (which shows "N secrets found" with Add and import them; `repos:inspect` returns only the count); Import (`importPlan.ts`) has a row per key and a column per environment with conflicts, gaps, an Unassigned lane, and options to rewrite open worktrees' copies (default on) and take the keys out of the main checkout's `.env`-style files (default off; never JSON, user secrets or tracked files). Injection (`inject.ts`, `spawnTerminal`): Setup, run/dev-server, test and (opt-in per secret) shell tabs get the task environment's values, plus `ASPNETCORE_ENVIRONMENT`/`DOTNET_ENVIRONMENT` (and `NODE_ENV` for run and shell tabs) and a matching `--launch-profile` for `dotnet run`, only when the repo has a stored secret; agent tabs never do; `copy:` writes env files without stored keys (`local.settings.json` `Values` keys matched without the `Values__` prefix; rewrites go through a temp file and rename, `replaceFile.ts`). Each task has an environment (New task picks it, Start uses the repo default, never UAT/Production); the task bar chip switches it and restarts only the tabs that hold secrets, by one rule (`holdsSecrets` in `inject.ts`: a stored value is given to the tab, so a shell that gets nothing is never stopped or restarted; the Setup tab is only stopped), and Restart of such a tab always builds its env again; UAT and Production need a confirm and show a band (amber/red), Production ends after `secrets.productionMinutes` (default 60, min 5; `expiry.ts`, checked every 30 s and on resume) and at Finish; the environment shows in the breadcrumb, tab labels, the Done page and the draft PR description. Leak watch (`LeakMatcher.ts`, `LeakWatch.ts`, `leakScan.ts`) masks every environment's stored values (and base64 forms, 8+ chars) in agent output as `[NAME]` with a notice, pauses the tab's input for a Production value (Resume / Stop), flags Changes rows, and Finish refuses a push whose commits add one (or that it could not check, `git log` given up after 60 s) until confirmed; the draft PR summary's `claude -p` gets the deny rules and its prompt and text are masked; values from tracked files are masked without a notice. `shellie run <name> [-- args]` (`RunHub.ts`, `shim.ts`, shims in `<userData>/bin`, `SHELLIE_RUN_URL` + per-task token) runs only named commands (`run:` entries, `test`, `setup`) in a visible `agent · <name>` tab with the secrets and returns masked output (no notice, no pause: the agent never sees a value) and the exit code; UAT and Production runs wait for an approve bar that shows the resolved script (package.json pre/post scripts, bidi controls marked); Claude's system prompt and OpenCode's instructions name the commands. Claude Code `--settings` and OpenCode's permission config deny reading the untracked secret files discovery found (`deny.ts`); Copilot has no equivalent. Clean worktrees (Secrets page, task bar) rewrites old copies and restarts the secret tabs. Discard (#124) also stops the task's `shellie run`s and drops its leak watch state. An unreadable `secrets.json` is moved aside with a start-up notice naming the backup. Telemetry `secrets.*` (counts, source kinds, the four environment names, booleans) in `docs/telemetry.md`. Verified live on macOS on 2026-10-23 on a fresh profile against a scratch repo (`.superpowers/sdd/2026-10-23-secrets/task-11-report.md`; the Claude Code tab was a stand-in shell with the agent environment, no model). Known gaps: `shellie run` and leak watch guard against accidental exposure, not a hostile agent (an agent can edit what a named command runs; UAT/Production approvals show the resolved script); leak watch detects, it does not prevent (the model has seen a value before it is masked); values split by more than 50 ms or by escape codes and multi-line values (PEM) are not matched in terminals; the tracked-file value list is kept for the app session (a file committed later is not known until a relaunch); framework environment spelling is not overridable per repo; Windows shims, cmd argument refusal, deny paths (Claude `//c/` form) and user-secrets paths verified by CI only; OpenCode's absolute-path deny for files outside the worktree and its `secrets/**` pattern unverified live.
