# Agents run tests in their own shell, never through shellie run

Issue #319, branch `fix/319-plain-tests` (2026-11-17).

## Problem

On Windows, an agent running the project's tests through `shellie run test` raised a Windows security prompt (the reporter: SmartScreen or UAC) that a managed work PC does not let the user accept. A plain `dotnet test` in a PowerShell window in the same repo shows no prompt. On that path the agent calls `shellie.cmd`, which starts `powershell.exe -ExecutionPolicy Bypass -File` on the unsigned shim in `%APPDATA%`, which calls curl.exe to Shellie on 127.0.0.1, and Shellie then runs the test command in a new PowerShell. The exact program the prompt named was not established. The owner chose to stop routing tests through Shellie in every repo rather than diagnose further.

## What changed

- `RunHub` (`src/main/secrets/RunHub.ts`) no longer offers `test`. The test command is no longer added to the names, a `run:` entry named `test` is left out too, and `shellie run test` is refused with exit 2: "Tests do not run through shellie run: run the repo's test command (dotnet test, npm test) directly in your shell, without this project's secrets." `RunBackend.testCommand` and `RunSpec.given: 'tests'` are gone.
- The agent instruction (`shellieRunInstruction` in `src/shared/naming.ts`) says tests run directly in the agent's shell, never through `shellie run`.
- The secrets import note, README and Windows checklist say the same. Telemetry `secrets.runStarted` no longer sends `kind: test`.

Run tabs the user starts and the Setup tab are unchanged. Secrets given to "tests" still reach a user-started run tab whose command is the repo's test command.

## Known gaps

- Tests an agent runs get none of the repo's stored secrets, so tests that need one fail in the agent's shell.
- `shellie run` for the dev server and other named commands still uses the same PowerShell shim on Windows. If the prompt comes from the shim and not from the test run, it will show up there too.
- Not run on Windows; unit tests on macOS only.
