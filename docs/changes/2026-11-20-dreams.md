# Dreams: project dreams for skills and rules

Branch `UnreliableWitness/dreaming-function-brainstorm` (2026-11-20). Spec:
`docs/superpowers/specs/2026-11-20-dreams-design.md` (with its "Changed during the build" section); plan:
`docs/superpowers/plans/2026-11-20-dreams.md`. Design canvas "Shellie Dreams":
https://claude.ai/artifact/UpRsPykwKeKdEo2iWdQoLn (snapshot in `design/mockups/dreams/`). Piece 1 of 4 of "dreaming".

The owner has a model licence (GLM 5.3, through OpenCode only) whose tokens go unused. While the machine is idle,
Shellie now goes back over a repo's past Claude Code and OpenCode task sessions on that model and proposes changes to
the repo's checked-in skills, rules and agents (`.apm/`), on a local branch the owner reviews in the morning.

## How it works

- **Settings and switching on** (`src/shared/dreams.ts`, `DreamSetupScreen.tsx`, `src/main/dreams/dreamHandlers.ts`).
  `dreaming` in the app settings: on, model, tested model, limit (tokens or euros a day, or none), repos with the
  folders a dream may change, idle minutes. Only `dream:switchOn`, with a tested model, a limit, a repo and the
  owner's tick, sets `enabled`; `SettingsStore.updateDreaming` is the only writer of the block. A widening change
  while on waits for the tick again and lists what it adds; a narrowing one applies at once.
- **When** (`scheduler.ts`, `ready.ts`). A check every minute: on, model in OpenCode's list (refreshed at most every
  10 min), idle, on mains power, no agent tab working, no dream running, room under the limit, a repo with new
  material and no open result. Dream now skips idle, power and busy only. Back-off 1 h, 6 h, then stop after three
  failures on the same material.
- **Material** (`material.ts`, `src/main/sessions/taskSessions.ts`). Up to 20 tasks of the repo, newest first, as
  digests plus an index in the dream's own data folder, with sightings (90 days) and rejections from `dreams.json`.
- **The run** (`DreamRunner.ts`, `dreamGit.ts`, `opencodeDream.ts`, `prompts.ts`, `report.ts`). A worktree on
  `dream/<date>-<n>` from the repo's PR target under `<userData>/dreams/<repoId>/<id>/wt`; a propose run, then a
  read-only check run, both `opencode run --format json --title "Shellie dream: …" -m <model>` with an inline config
  that pins every model and allows no shell, web, MCP or subagents; Shellie reverts anything outside the allowed
  folders, commits each proposal that passed the check (hooks off), and checks every assistant message of both
  sessions against the chosen model. Before the check run Shellie writes the propose run's changes to `changes.diff`
  in the data folder (git's diff of the worktree against the base, untracked new files included, hooks off, cut at
  2 MB with a closing line saying so); the check prompt (version 4) says the worktree already holds the proposals,
  that the diff shows what they added and removed, and that "repeats or contradicts an existing source" means what
  was in the repo before them. Another model throws the dream away, switches dreaming off and clears the
  model's passed test, so switching on again needs a new test.
- **Evidence** (`evidence.ts`). Shellie checks each quote against the turns of the task it names: the quote is
  cleaned (a leading `**Developer:**`/`**Claude:**`/`**Agent:**` label, quotation marks around it as a matching pair
  only, and spare whitespace off; cut at a label inside) and looked for inside one turn, case-sensitively, on word
  boundaries at both ends (Unicode letters and digits), at least 3 words and 12 characters: `you` for a developer
  turn, `agent` for an agent turn, else `unknown`. Who said each quote is decided before the cap of three and the
  merge of proposals sharing a file: a proposal without a `you` quote counts as failed by the check, so it takes no
  place and joins no kept group. The result screen captions quotes "You, in", "The agent, in" or "From", unknown
  ones last. Both prompts ask for the developer's own words, copied exactly, without the label.
- **Limit and cost** (`limit.ts`, `src/main/budget/openCode.ts`). Dream usage is read from OpenCode's database by the
  title prefix, checked every 30 s during a run; dream sessions are kept out of task sessions and get the ledger
  level `dream`, never sent to the cost server.
- **Screens.** Dreams (navigation item with a count), the result review (`DreamScreen.tsx`: drop and undo, evidence,
  git's own hunks, a full diff), the Home band, the status line at the foot of the navigation with its panel, and a
  Dreaming section in Settings. Open as task makes a normal task on the dream branch with the kept proposals.
- **Telemetry** (`dreamTelemetry.ts`): `dream.enabled`, `dream.switched_off`, `dream.test`, `dream.run`,
  `dream.result`, and screen views `dreams`, `dream-setup`, `dream`; enums, counts and booleans only, listed in
  `docs/telemetry.md`.

## Decisions made during the build

Beyond the spec (the ledger's rulings, in plain words; the spec's "Changed during the build" lists those that change
what it says):

- `--pure` is not passed, so the owner's licence provider keeps working if it needs a plugin; instead
  `OPENCODE_DISABLE_PROJECT_CONFIG=1` stops the repo's own `opencode.json` and `.opencode/` from loading, and
  inherited `OPENCODE_*` variables are removed.
- A dream may never write OpenCode's config (`opencode.json(c)`, `.opencode/`) or anything in a folder named
  `hooks`; such paths cannot be chosen as allowed folders and are reverted after a run.
- The check run is read-only, enforced twice: the edit permission and a compare of the worktree's changed paths
  (ignored files too) before and after it; a difference fails the dream ("The check run changed files").
- Shellie's dream commits run with hooks off and without signing.
- Failure reasons are fixed phrases, never session text, paths or git's own errors.
- The startup cleanup deletes a `dream/…` branch only when its dream folder exists; a dream opened as a task keeps
  its branch.
- OpenCode turns now carry their times, so an OpenCode-only task is dreamt again when it has new turns.
- A stored "switched itself off" always wins and is cleared only by switching on.
- Dream ids are per repo: every lookup is by repo and id. A dream never reuses an id the journal names (fix in Task 13).
- Opening a dream as a task never deletes the dream branch on a setup failure or cancel, and survives a restart.
- Every setup control shows the saved settings or the held draft; picking a model tests it at once.
- A held widening lists what it adds (`widenings`), since the sentence does not name folders.
- The "found nothing" line stays inside the Home band, for the newest journal line under 24 hours.
- The changed lines come from git (`dream:diff`, with caps), the two texts of one file on demand (`dream:file`).
- The monthly Claude and Copilot budget bands keep counting by provider; a dream on such a provider counts there.
- Evidence is checked against the turns, not trusted: a proposal rests on at least one quote of the developer
  (owner's coordinator ruling after the first check); the stored quote is the cleaned one.
- A wrong-model switch-off clears `testedModel` in the same write, so Test the model again is a real precondition.
- The check run judges against the sources as they were (finding of the 60-call real run, see Verified): it gets
  `changes.diff`, and must never fail a proposal because its own added text is now in the file. The read-only
  compare looks only inside the worktree, so `changes.diff` (in the data folder) does not trip it.
- A quote is the developer's only on whole words (a review finding: "use the helper" matched inside "refuse the
  helpers"), with at least 3 words and 12 characters; a lone apostrophe is never stripped as a quotation mark.
- Evidence is decided before the cap and the merge (a review finding: a fourth proposal with a real quote was
  dropped while three without one took the places, and a merged group could carry a member's unsupported change).
  The runner marks such proposals failed in its copy of the report before `groupProposals`, which stays pure.

## Not verified, and known gaps

- Not run on Windows (spawning, paths, the worktree folder length, killing the run's process tree).
- Not run on the owner's licence model (GLM 5.3) or provider; whether its provider needs a plugin, and how good the
  proposals are, is unknown. Real `opencode/big-pickle` dreams ran four times (one stopped at an 8-call cap), all on
  one invented session.
- No real pull request: Finish on a dream task was seen only up to its offer, on a repo without an Azure DevOps
  connection, so the pull request offer and its target branch were not seen.
- apm's source folder (`.apm/`) is assumed from apm's docs; the owner's project repos were not checked.
- A real model that paraphrases a quote will have its proposal removed.
- A rejected idea can come back: the last real dream re-proposed three ideas the rejection list names.
- `changes.diff` leaves out ignored files, and builds a temporary index, which rehashes the worktree's files (slow on
  a very large repo; the new files' blobs stay in the repo as loose objects until git's own clean-up).
- The Home band sits below Get started on a fresh install (the canvas has it at the top); the canvas's journal summary
  line ("This week: 6 dreams …") is not built; the Dreams title row has its buttons on a row of their own; the full
  diff opens in place, not in Changes as the canvas says; the "found nothing" line was not seen in the app.
- The setup test's tokens count toward the day's usage; the dream calls show in the Claude budget band's "Not in a
  budget" line.
- A repo's OpenCode `provider` override, global plugins and `~/.opencode` still load; repo MCP servers may start
  (their tools are denied); a console or managed config merges after the inline one.
- macOS stops only the OpenCode process on Stop, not its children.
- `next` (which repo dreams next) is often unknown until the repo's sessions were read; a task that joined a repo
  only as an extra workspace is not material for it.
- Three model-list caches (renderer, handlers, scheduler); a dream branch stays a plain branch when no task is made
  within 10 minutes of Open as task; a narrowing that leaves nothing to run switches dreaming off.
- If neither the switch-off record nor the settings can be written after a wrong model, dreaming is on again after
  a restart.
- A dream task's setup steps read "Restore worktree" and "Restore terminals".
- A dream folder of a repo Shellie no longer knows leaves a prunable worktree entry; fetch, worktree remove and
  branch delete in the main checkout still run the repo's reference-transaction hook.
- Minor, deferred from review: `confirmSentence` on a null limit or zero repos; `normalise` strips only a leading
  `./`; quotes and reasons are not folded to one line in `index.md`; two timing cases in the setup's stale-view
  logic; no way back to "no model" after a failed first pick; a mode-only change shows +0 −0; non-UTF-8 files are
  decoded lossily; one `dream:changed` makes each mounted dream view fetch once.
