# Start asks which repo when several share a project

Start asks which repo to use when several repos share a project (#164) on `agent/issues/164-no-support-for-two-repositories-connecte`. Until now, Start on a Sprint row or in Home's Up next always created the worktree in the first repo linked to the Azure DevOps connection. Now, when more than one (non-discovered) repo is linked to it, Start opens New task with the work item and the first of those repos already filled in, so you choose the repo in the Repo dropdown. With one repo, Start still creates the task in one click; with none, it stays unavailable. New task also keeps the picked work item when you switch to another repo on the same connection (it used to drop it on any repo change). Known gaps: no remembered repo per work item or area path; the generic New task button still defaults to the first repo; not checked in the running app.
