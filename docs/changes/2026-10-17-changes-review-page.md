# Changes review page

Changes review page (spec `docs/superpowers/specs/2026-10-17-changes-review-design.md`) implemented 2026-10-17 on `feature/changes-review`: a Changes pivot with All changes (base to working tree, committed or not), Uncommitted and commit scopes in the Monaco diff editor, viewed files that clear when the content changes, comments on lines kept in `review/<taskId>.json` that move with the code, go outdated and can be sent to an agent tab, a Finish reminder, and Open in VS Code or Visual Studio chosen per repo (Settings > Editor). Multi-repo tasks in Changes (spec `docs/superpowers/specs/2026-10-17-changes-multi-repo-design.md`): each repo has a color (`repoColor`, `--repo-1`…`--repo-6`) shown on the task chips, the terminal menu and in Changes; a foldable header per repo (files, lines, viewed, comments, uncommitted; folds by itself once all viewed, a hand-made fold lasts until a file changes); a "No changes · not in Finish" row from Finish's own rule (`dropsAtFinish`); filter chips and keys 0-9 (a commit pick narrows to its repo and locks the others); the repo in the diff's breadcrumb. Known gap: at narrow widths the task's tab row and the repo chips overlap (the chips do not shrink), which predates this. Fewer controls (#64, PR #65 merged into the #63 branch after #63 had merged, so it reached main with #72): a multi-repo task has one "3 repos" chip in the task bar (its menu has each repo's git state, New shell here, Open in editor, Remove from task), the repo filter is one dropdown, Changes has no second Open in editor, the comment count and Send show only with open comments, the diff options sit in a View menu and the file arrows are icon buttons; the task bar's commands never shrink, the tab row clips instead, and a narrow bar (container queries) hides the branch name and the Open in label, then the git state. Comment cards in the diff are Monaco overlay widgets over an empty view zone (#71: view zones sit under the text layer and take no clicks). Issues #73-#76 (2026-10-19): the task bar's main button is Open folder (shell.openPath), editors sit in its menu, and Windows starts VS Code through Code.exe next to bin\code.cmd (#73); the apm setup step puts tracked files apm install rewrote (apm.lock.yaml) back to HEAD (#74); Changes rows have Discard changes / Delete file with an in-page confirm bar, Uncommitted restores to HEAD and All changes to the base, never in a commit scope (`review:discard`, #75); Docs defaults to a Session view: a tree of Markdown files the task's Claude sessions wrote (from transcripts, also outside the worktree, whitelisted for docs:read) plus Markdown changed against base, with an All docs toggle (`docs:session`, #76). Visual Studio detection (#94): vswhere with `-all -products * -prerelease -format json` (Insiders and not-yet-launchable installs, the newest devenv.exe), vswhere under Program Files (x86) or Program Files, then the registry's App Paths entry, then the default folders (2026 is `18`); the editor menu detects again each time it opens, lists every installed editor plus Visual Studio's solutions (root and up to two folders down) whatever the choice, and Visual Studio opens the folder when there is no solution.
