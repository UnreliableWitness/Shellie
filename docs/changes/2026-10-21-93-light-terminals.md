# Light terminals

Light terminals (#93, 2026-10-21, `fix/light-shell`): light terminals use a soft off-white ground (`--bg-terminal` #f7f6f4, the padding too) with softer text, GitHub Light ANSI colours darkened to at least 4.5:1, and xterm's `minimumContrastRatio` 4.5 in light only (`terminalTheme.ts`); terminals get `COLORTERM=truecolor` and `COLORFGBG` for the scheme at spawn. Claude Code tabs pass `--settings <userData>/claude/claude-theme-<t>.json` (a file, since PowerShell 5.1 mangles inline JSON): `auto` for the user's dark/light/none, the scheme's variant for -daltonized and -ansi, nothing for a custom theme (`src/main/services/claudeTheme.ts`; the user's own settings are never written). `auto` asks xterm for the background (OSC 11); `TerminalManager` sees programs turn on mode 2031 and, after the renderer re-coloured a terminal (`terminals:reportScheme`), sends `CSI ? 997 ; 1|2 n`, so Claude Code redraws in the new scheme live. Verified with claude 2.1.303 and 2.1.306 on macOS; Windows (whether ConPTY passes mode 2031 and OSC 11 through) unverified, COLORFGBG covers the start there. Colour-blind and ANSI-only themes (#105, 2026-10-22, `fix/claude-retheme`): Claude Code has no auto for them and does not reload `--settings` while running (checked on 2.1.307), so a tab started in light kept the light-daltonized prompt bar in dark; after a scheme change `ClaudeRetheme` (`src/main/services/ClaudeRetheme.ts`) resumes each such tab in the new variant once it is idle (no working or blocked status, output quiet 2 s, nothing typed since the last Enter), and the view clears on `terminal:reset`.
