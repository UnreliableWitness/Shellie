# What the agent of an ask is doing, as it does it

Date: 2026-11-28. Step 2 of six of `docs/superpowers/specs/2026-11-28-ask-everywhere-design.md` (the owner's sweep
of thin features, see `2026-11-28-ask-shared-states.md`); plan
`docs/superpowers/plans/2026-11-28-ask-step-2-steps.md`.

## What changed

- **Steps.** While a brain question or a dream ask runs, the ask shows what the agent did, a short line each
  ("Read wiki/connections.md", "Searched for “retry”", "Edited rules/b.md"), above the time and Stop. A finished
  ask keeps them behind a fold ("3 steps"); a brain answer's foot says "read N pages".
- **Written out.** On Claude Code a brain answer appears as it is written, under the steps; the final answer
  takes its place. OpenCode reports a step when the tool has finished and gives its answer whole, so there the
  steps come one by one and the text at the end.

## How it works

- `runWithInput` (`src/main/services/prSummary.ts`) takes `onLine`: each whole line of standard output as it
  arrives, decoded as a stream (a chunk may end inside a character), cut at 65 536 characters. The promise still
  resolves to the whole output. Runs in production happen in the pty host, so its protocol has a `lines` flag on
  `run` and a `runLines` message, sent every 250 ms and always before the run's end.
- `src/main/ask/steps.ts` reads one line of either agent's events into a step or a piece of text. The shapes, as
  seen on the installed CLIs (OpenCode 1.19.3, Claude Code with `--output-format stream-json --verbose
  --include-partial-messages`), are recorded in the plan. `progressLog` collapses a repeated step, keeps the
  newest forty, and emits at once and then at most four times a second.
- What a step may show: a path inside the run's folder (forward slashes, one line, its last 120 characters when
  longer), else "a file outside the folder"; a search pattern cut at 60 characters, and not at all when it is
  absolute or holds `..`; a tool's name only when it is a plain word. Never tool output, never thinking.
- Main sends `ask:progress` (`{ key, steps, earlier, text }`; keys `brain:<taskId>`, `dream:<repoId>`), an empty
  one first for each run. The renderer keeps the last per key (`askProgress` in the store) and `AskWorking`
  draws it (`components/ask/AskSteps.tsx`). The store also forgets a task's progress when it asks again.
- The brain's question (`src/main/brain/ask.ts`): the flags change from `json` to the stream; nothing about what
  the run may do changes (`--tools Read,Glob,Grep`, `--strict-mcp-config`, OpenCode's deny rules). The answer is
  taken from the result line as it passes, because a long run prints more than the runner's 4 MB and the result
  comes last. `BrainAnswer` gains `steps` and `pagesRead`.
- The dream's ask (`dreamHandlers.ts` `runAsk`): `dreamCall` passes `onLine`; files in the dream's data folder
  (the agent's own note for Shellie, the session digests) are not steps. The row gains `steps`, also when the run
  was stopped or could not finish.

## Verified

- `npm run typecheck`, `npm run lint`; the renderer tests and the main tests for ask, brain, dreams, the pty host
  and the runner pass (2576 tests in the last run).
- A fresh reviewer read the branch: no critical finding; its two important ones are fixed (a follow-up showed
  the answer before as if it were coming; a search pattern could show a path outside the folder), and so are a
  late update after Stop and unbounded path labels.
- In the running app on macOS, dark and light: on the free OpenCode model, a brain question whose steps arrived
  one by one, its foot and fold, Stop with nothing arriving after, Ask again starting empty; a dream ask with
  "Read" and "Edited" above "Working" and the fold on the finished row. One short Claude Code question on Haiku
  (the owner's subscription): steps per tool call and the answer appearing in pieces, then the final answer.
- That check found "Wrote a file outside the folder" on every dream ask (the agent's note), a stale step at the
  start of a follow-up and a long link in an answer widening the tab; all three are fixed, after the check.

## Known gaps

- The fixes made after the app check were not seen in the app. Windows was not run.
- A follow-up in a thread that began on another agent (the brain switched between OpenCode and Claude Code)
  fails with the CLI's own words about the session id. It did before; step 3 of the design starts a new session.
- A Claude Code result line longer than 65 536 characters is not kept from the live lines; it is still read from
  the collected output unless that passed 4 MB too.
- `pagesRead` counts among the forty steps kept, and counts "a file outside the folder" as a page.
- Only the first tool call of one Claude Code message becomes a step.
- The text so far is sent whole on each update; an unfinished diagram in it is handed to the renderer each time.
- `askProgress` keeps the last entry of a removed task or repo until the app restarts.
