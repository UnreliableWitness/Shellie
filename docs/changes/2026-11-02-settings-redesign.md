# Settings shaped like VS Code's, with everything about a repo in one place

Settings redesign (spec `docs/superpowers/specs/2026-11-02-settings-redesign-design.md`, plan `docs/superpowers/plans/2026-11-02-settings-redesign.md`) implemented 2026-11-02 on `feature/settings-redesign`. Settings is one page with a search box (title, description, category and keywords; categories without a match hide, an empty result says so, a hit in the other scope shows "N results in Repository/User" and switches on click; Cmd/Ctrl+F focuses it), scope tabs User | Repository (repo dropdown with discovered repos marked, Add folder…, the last scope and repo remembered in `shellie.*` localStorage), a category tree with scroll spy, and uniform rows (`SettingRow` in `src/renderer/components/settings/`: "Category: Name", description, control, source label, a blue `--accent` bar when not the default, a gear menu with Reset). Saving stays immediate except the sections that had a Save button (cost port, time, budgets, cost server).

Repo settings are personal overrides on the repo record (`Repo.overrides` in `state.json`, carried through `RepoRegistry.describe`), merged as Shellie's defaults < `.shellie.yml` < your override by `mergeConfig` (`src/shared/repoConfig.ts`), which every reader of the config uses (setup, Start, New task, run tabs, reopen, extra workspaces, Changes' collapse list mapped from the worktree back to its repo). `repos:setOverride(repoId, key, value | null)` and `repos:clearOverrides`; `repos:config` returns the effective config, each key's source (`default`, `file`, `override`), the file's own values and a `fileError`. Lists are overridden as a whole. Rows show "Default", "From .shellie.yml" or "Modified by you"; Reset brings back the file's (or default) value. `.shellie.yml` is written only by the explicit "Create .shellie.yml" link in the repo header (keys that differ from the defaults, then the overrides it wrote are cleared). A broken file shows a banner; rows then show defaults plus overrides.

Repository scope categories: Secrets & env (the Secrets manager's status panel, secret count, default environment, the files copied into each worktree with a state per entry: Present, Missing, Holds secrets, Not ignored by git, Outside the repository; Reveal, Remove, Add file… with suggestions; Copy agent config), General (base, branch pattern with a live preview, connection, Found in a task), Setup (setup commands list editor, apm Automatic / Off / a list), Agents (#191's commands), Run, Work items on start (all types listed, disabled without a connection), Editor, Changes (collapse), Danger zone (Remove with a confirm bar). User scope: Connections, Secrets (one row per repo with its status, Manage, Import…), Editor, Agents and terminals, AI cost and invoicing, Time tracking, Budgets, Cost server, Appearance, About, each as rows. Deep links (`repos`, `terminals`, `ado`, `conn-<id>`, `budgets`) still work and take an optional `repoId`.

New task shows a "This task will…" card (`TaskSummaryCard`, `src/shared/setupSummary.ts`) above "Setup from .shellie.yml": branch and base, env files with their state (missing or not ignored as a warning), setup commands and apm, the tabs it opens, run commands, the work item action and the editor, each with an Edit link to the setting. The task records what it was given (`TaskSetup.summary`), and the setup page shows that, collapsing once setup is done. Telemetry: `settings.scope`, `settings.search` (result count, never the query), `settings.repoOverride` (key and reset, never the value), `settings.copyEntries` (counts per state) in `docs/telemetry.md`.

Verified live on macOS on 2026-11-02 on a fresh profile (`SHELLIE_USER_DATA`), with this repo (no `.shellie.yml`) and a scratch repo with one: search and its empty state, the other-scope link, both scopes, a setup command override showing "Modified by you" and reaching New task's card, the card's Edit link opening Repository › Setup on that repo, Reset bringing back the file's commands (and the card following), Secrets in both scopes, light and dark. No task was created and Azure DevOps was not touched.

Known gaps: the gear menu has Reset only (the spec's "Copy value" was not built); no Visual Studio solution picker per repo (no IPC lists solutions without a task; the old row had none either); the "same as .shellie.yml" hint is skipped; the setup card does not say "node_modules cloned" (decided at setup time); with a `.shellie.yml` that has no `base`, the base comes from the repo's stored base, not a fresh detection; Reset shows on work item rows that are disabled for a repo without a connection; Import… shows in the repo scope even when nothing can be imported; New task still defaults the base to `origin/<base>` for a repo without an `origin` remote (older gap); overrides are personal, there is no way to write them back to the team's `.shellie.yml` except Create when there is none; Windows verified by CI only.
