# Setup steps that hang fail with a named error

Setup step timeouts (2026-10-26, #148, `agent/issues/148-setuprunner-extra-worktree-test-hangs-on`): the Windows CI test "restores an extra worktree from origin/<branch> and runs its commands there" sometimes hung until Vitest's 60 s limit, with no hint which step was stuck. `GitClient.worktreeAdd` (including its `rev-parse HEAD`) and `worktreeAddExisting` now run with `worktreeTimeoutMs` (default 5 min, generous for a large checkout or a git-lfs hook; set in the constructor like `pushTimeoutMs`) and fail with `git worktree add timed out after <s> s`, killing git and its helpers through the existing `execWithTimeout`/`killTree` path (`killTree` is now exported). `SetupRunner.spawnLogged` takes a deadline: `apm --version` gets 30 s, other commands only get one when the runner is built with `commandTimeoutMs` (none by default, since `npm ci` can run long); a timed-out command's process tree is killed and the step fails with `<cmd> timed out after <s> s`, in the log and the failed step's detail. `spawnLogged` also settles 2 s after the process exits even if a helper it left running still holds the stdout/stderr pipes, which `close` would wait for. The setup tests use 30 s deadlines for both, so a hang fails before the test's 60 s with the step's name.

Not verified: the Windows cause was inferred (a lingering PowerShell or git helper holding the pipes, or a stuck `worktree add`) and not reproduced; only repeated Windows CI runs can confirm the hang is gone.
