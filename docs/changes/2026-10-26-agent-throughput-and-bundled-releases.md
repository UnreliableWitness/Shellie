# Agent throughput and bundled releases

After the first full day of the agentic SDLC (2026-10-26, `UnreliableWitness/agents-throughput`), two issues logged at 10:53 were still open at 18:30: triage took minutes, but every issue waited in a queue with one agent PR slot, PRs lost hours to flaky CI that the fixer could not fix, and features always waited for the owner. Changes, on the owner's decisions:

- **Three agent PRs at once** (`maxOpenAgentPrs: 3`); after publishing a PR, the implement workflow starts itself again (`gh workflow run` with the workflow token), so the next ready issue starts at once. A run that picks nothing opens no PR and starts nothing.
- **A red CI is re-run once per head commit** before a fix round (`decidePr` action `rerun`, `prState.ciRerunSha`; the decide job has `actions: write` and passes the workflow token in a file, since the App may only read Actions).
- **"Nothing to change"**: the agent jobs count their own commits (`result.commits`, first-parent); a fix with none goes to the owner with the fixer's note instead of another round, an implementation with none is a plain failed attempt. Before, both reported a misleading "could not open branch.bundle".
- **Low-risk features merge like bugs and chores** (the owner's call); high risk, size, owner-only files, a red `main`, holds and the owner's Request changes still stop a merge.
- **Releases are bundled**: a push to `main` only runs the tests (6 min, so the agents merge the next PR sooner); `ci.yml` releases on its schedule (11:00 and 16:00 UTC: 12:00 and 17:00 Brussels in winter, 13:00 and 18:00 in summer), on "Release now" (workflow_dispatch on `main`) and on a hand-pushed `v*` tag, when `release-needed` finds app changes since the last tag. At the merge the reporter is told the fix ships with the next release; the late-release warning moved from 90 minutes to 26 hours.
- **ChangesTab selection race** (the test that failed most on CI): the auto-select effect read the selection from its own render, so a file clicked just before it ran (a slow machine, right as the list appears) was set back to the first file. It now decides on the current selection (function setter). Not reproduced as a deterministic test; the CI test that failed is the regression check.
