# macOS release

macOS release (spec `docs/superpowers/specs/2026-10-24-macos-release-design.md`, owner setup and manual check in `docs/macos-release.md`) implemented 2026-10-24 on `feature/macos-release`: every release also carries `Shellie.dmg` and `Shellie-darwin-arm64-<version>.zip` for Apple Silicon (Intel is not supported). The `macos-release` job runs after `windows-release`, reuses its tag, and with all five Apple secrets (`APPLE_CERT_P12_BASE64`, `APPLE_CERT_PASSWORD`, `APPLE_API_KEY_P8_BASE64`, `APPLE_API_KEY_ID`, `APPLE_API_ISSUER`) and the variable `APPLE_TEAM_ID` it signs in a temporary keychain (`tools/forge/macSigning.mjs`, `assets/entitlements.mac.plist`), notarizes with the App Store Connect API key and uploads with `gh release upload --clobber`; without them it builds unsigned and uploads a run artifact only, never to a Release, and the step summary names the missing secrets. A failed macOS job never blocks the Windows release; retry with "Re-run failed jobs". Packaged macOS builds auto-update through update.electronjs.org (`darwin-arm64`) only from `/Applications` (`app.isInApplicationsFolder()`); elsewhere a quiet `MoveNotice` card ("Move Shellie to Applications to get updates", Move / Not now; `update:needsMove`, `update:moveToApplications`) offers to move the app. Known gaps: the first signed build, notarization and the vN to vN+1 update (including that Restart and update gets past the `will-quit` 2 s hold in `src/main.ts`) are unverified until the owner's setup; entitlements are `allow-jit`, `allow-unsigned-executable-memory`, microphone, camera and Apple Events (for CLIs in terminals; `disable-library-validation` may still be needed, decided by the first signed run); the DMG itself is not signed or notarized (the `.app` inside is).
