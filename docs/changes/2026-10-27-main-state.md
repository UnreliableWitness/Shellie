# A red main no longer blocks merges silently

On 2026-10-27 three green, reviewed, low-risk agent PRs (#166, #168, #169) waited about four hours (`UnreliableWitness/agents-main-state`). The last push CI on `main` (10:57) had failed on a flaky macOS test (`handlers.part6.test.ts`, "shellie run … visible agent tab"), the agents merge nothing while `main` is red, and without a merge nothing replaced that run: a deadlock. The scheduled CI runs on the same commit passed at 11:16 and 16:15, but the check read push runs only. Now `mainState` (`tools/agents/pr-decide.mjs`) judges `main`'s current commit (`gh.mainSha()`) by every CI run on it (push, schedule, manual): green when any passed; while one runs it waits; a failed run is re-run once (the decide job's workflow token); still red after that, the decide step opens one issue labelled `agent:main-red` and `agent:needs-owner` ("main is red: the agents have stopped merging"), and closes it with a comment once `main` is green.
