# Faster CI

Faster CI (2026-10-26, `UnreliableWitness/faster-ci`): CI runs once per PR (`push` only for `main` and `v*` tags, plus `pull_request` and a manual `workflow_dispatch`; before, every PR ran twice); lint and typecheck run on macOS only; the Windows suite (~15 min on one runner against ~3 on macOS, mostly real git and processes) runs as three `vitest --shard` jobs at once (`test-windows`, "test (windows-latest, part n/3)") summed up by one check still named `test (windows-latest)`, so required checks and the agents' `REQUIRED_CHECKS` are unchanged; the Windows installer no longer waits for the tests (the release jobs still need `test` and `test-windows`). Turning Windows Defender off on the runner was tried and measured no faster. The split showed one file held almost all of the Windows time: `handlers.test.ts` (249 tests with real git, 89 s locally, 13+ min on Windows), which a shard cannot divide; it is now `src/main/ipc/handlers.part1..6.test.ts` with the shared setup in `handlersHarness.ts` (`harness()`, cleanup, helpers), which also runs it in 35 s locally since files run in parallel.
