# Brain: every picture interpreted

Spec: `docs/superpowers/specs/2026-11-07-brain-picture-coverage-design.md` (mockups in `docs/superpowers/specs/assets/2026-11-07-picture-coverage-*.png`). Follows `2026-11-04-brain-images.md` and `2026-11-04-brain-images-2.md`, which get pictures into `sources/`; this change checks that each one was looked at and its meaning written into the brain.

## What changed

- **Four statuses, computed by Shellie** (`src/main/brain/pictures.ts`). The pictures of a source are the files in `sources/<stem>-assets/`; the wiki mirror's `sources/wiki/.attachments/` count as one source, `sources/wiki`. A picture is **described** when any link or image under `wiki/**/*.md` resolves to the file (a `#slide-N` anchor on the source does not count), **nothing to record** when `brain/pictures-skipped.json` (written by skills only) has it with a reason, and **not interpreted** otherwise. Pictures that **never reached Claude** are recorded at add time in `brain/pictures-dropped.json` (written by Shellie only; the brain's `.claude/settings.json` denies skills every write to it) with where, why and what to do; "Fine, I know" sets `accepted` and the drop stops counting as a gap but stays listed. Tiny PDF images are counted, never flagged. Link targets keep CommonMark's angle form, so `[d](<../sources/a b-assets/p4-1.png>)` resolves; a bare target with raw spaces is not a link the in-app renderer shows and does not count. Labels ("Slide 4", "Page 3", "Slide layouts and master") come from the asset names (`pictureLabel.ts`), the alt text from the source's `![alt](…)`.
- **Converters report each drop** (`convert/types.ts`, `pptx.ts`, `docx.ts`, `pdf.ts`): over the 60 cap, a format that could not be converted (EMF and WMF on macOS), too many pixels, the PDF render cap; each with a `where` ("Slide 1, picture 61", "Page 3, picture 2") numbered by its place in the document, taken or not. The warnings on the source stay as they were. `addSource` writes the record and rolls it back with the source on failure; the wiki mirror records its picture attachments it cannot view (not linked PDFs or documents) under `sources/wiki` at each refresh, keeping `accepted` for drops still there, in the mirror's own commit.
- **Skills v6** (`templates.ts`): `/capture` and `/sync` describe each picture they opened on a page with a link to the picture file as the citation, or add it to `brain/pictures-skipped.json` with a reason (keyed by the plain repo path, no `./`, no URL encoding); a picture that carries knowledge is never skipped and one that could not be opened stays unmarked. A new `/pictures <source> <JSON array of paths>` skill does the same for exactly the listed pictures and may update existing pages. Existing brains get "Update skills" in Settings › Brains.
- **Re-evaluation** (`jobs.ts`, `createPictureHooks` in `pictures.ts`, wired in `main.ts`): a `pictures` job kind. Its prompt is built when the job starts (`promptFor` → `picturesPrompt`), from the gaps at that moment; with none left it ends without running Claude ("Nothing to re-evaluate"). After a capture that ends ok with pictures not interpreted, `afterPictureJob` queues one pictures job for that source; a pictures job never queues another. A mirror refresh that brought new or changed attachments queues one for `sources/wiki`. After that, Re-evaluate (source panel, Health finding) queues one more per press; both buttons read "Re-evaluating…" and are disabled while a pictures job for that source is queued, running or paused. A capture queues no pictures job when one for its source is already coming, and a pictures job queued by hand (Re-evaluate, the mirror refresh) replaces a background one still waiting for the same source. All of this needs skills v6 (`picturesReady`, one threshold in `shared/brain.ts`): below it no pictures job is queued after a capture or a refresh, `brain:run` refuses one ("Update skills to re-evaluate pictures"), a stray one ends without Claude, and the panel and Health show "Update skills to re-evaluate" instead of the button. The jobs share the runner's lock, model, daily cap, pause and telemetry.
- **Earlier sources** (`runPicturePass`, `scheduler.ts`): once a brain's templates are v6, a scheduler tick (never the launch tick) rebuilds the drop records of sources added before by converting each stored original again (once; a source without an original has none), then queues one **background** pictures job per source with gaps, oldest first, the mirror last, skipping sources that already have a capture or pictures job coming. Its first run fixes what it covers (`picturePass.sources`: the captured sources with gaps, and the mirror); a resume only queues those still with gaps, so a source added later, or one not captured yet, is left to its capture. An original whose conversion throws gets an empty record too, so it is tried once. Background jobs run only when no normal job is queued. A done pictures job on a pass source (its own, or a Re-evaluate that replaced it) marks it done; a failed one counts in `picturePass.failures` and the source is given up at the second failure. The pass is saved on the brain record (`picturePass`: total, sources, done, failures, finished) and resumes after a restart; What runs by itself shows "Picture check for earlier sources" with its progress while it runs. Health counts pictures without reading any source for alt texts, and a `brain/pictures-dropped.json` that is not valid JSON is refused, never overwritten (readers treat it as empty).
- **UI**: a Pictures panel above the source text in Read (counts, a bar, the first 5 rows then Show all, lazily loaded thumbnails that open full size, the pages that describe each, skip reasons, drop reasons with fixes and Fine, I know, Re-evaluate while any picture is not interpreted) and a warn tag on the source header; the wiki mirror's pictures on `sources/wiki`, reached from its Health finding. Health gets a Pictures fact line ("211 of 214 interpreted · 1 not interpreted · 2 never reached Claude") and one `picture` finding per source with gaps, with Re-evaluate or Open source. The inbox and a task's Brain tab show the drops under a just-added source, then "re-evaluating N pictures…" while that runs and a green tag once all are interpreted.
- **Telemetry**: `brain.job` kind `pictures`; `brain.screen.action` `reevaluate` and `accept-drop` (`docs/telemetry.md`). No `brain.pictures` event.

Every job committed its output; the brain's working tree was clean after each.

## Known gaps

- Re-evaluating earlier sources costs real usage: older skills cited `sources/x.md#slide-4`, which does not count, so the one-time pass queues a job for nearly every source with pictures. The daily token cap pauses the brain's lane like every brain job: it goes on after Resume in What runs by itself or after a restart, not by itself the next day.
- A pass started before `picturePass.sources` existed (a build of this branch) has an empty list: its next run finishes it without queuing more.
- EMF and WMF still never reach Claude on macOS; they are listed as never reached, with the fix.
- "Described" means a page links the file, not that the description is good.
- Claude may mark a picture skipped when another source's copy of it is already described (seen live: "repeat of the order flow diagram already described"). The knowledge is in the brain, but cited from the other source's file.
- A source's alt text is read only from a bare link target, so a picture linked in angle brackets (a path with spaces, only possible for a file placed by hand) shows no alt text in the panel.
- The wiki mirror's pictures have no entry in the source tree; they are reached from their Health finding.
