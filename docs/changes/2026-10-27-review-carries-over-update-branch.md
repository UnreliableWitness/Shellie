# A review carries over "Update branch"

On 2026-10-27 three approved agent PRs (#166, #168, #169) were brought up to date with `main` by the agents (GitHub's update-branch), which gave each a new head commit, and a new head needed a new full review (an Opus run each), while the day's 30 runs were used up: all three waited for midnight UTC (`UnreliableWitness/agents-carry-review`). Bringing a PR up to date does not change its own code (GitHub refuses update-branch when there is a conflict), so now a review carries over: `carriedReview` (`tools/agents/carry.mjs`) walks back from the head through GitHub's merges of main (two parents, "Merge branch 'main' into …", committed by GitHub; at most 10) to the last reviewed commit and reuses its verdict (`carriedFrom`); a failed review never carries over, and any other commit (the fixer's, the owner's) still gets a review. Both the reviewer (which runs first in `agents-pr.yml`) and the decide step use it, so after every merge the other open PRs merge without new review runs.
