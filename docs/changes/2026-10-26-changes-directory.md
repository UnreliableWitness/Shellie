# Change notes in docs/changes/

One file per change in `docs/changes/` (2026-10-26, `UnreliableWitness/changes-dir`) instead of a line in the Status section of `CLAUDE.md`. Every PR, the agents' included, added its line at the same place there, so any two open PRs conflicted: agent PR #141 needed a fix round for it twice. The 30 per-change entries moved here word for word, one file each (`YYYY-MM-DD-[issue-]topic.md`, the title from the entry); `CLAUDE.md` keeps what stays true (running and checking, telemetry rules, the Azure DevOps test project, where specs live) and went from 65 KB to about 4 KB, which every session loads. The agents follow: the implement skill writes a note here, triage greps these notes for known gaps, the reviewer expects a note and no `CLAUDE.md` edit, `CLAUDE.md` is owner-only for agent PRs (`OWNER_ONLY` in `tools/agents/publish-checks.mjs`; the earlier "only adds lines" exception is gone), and notes here do not count toward the 400-line auto-merge limit.
