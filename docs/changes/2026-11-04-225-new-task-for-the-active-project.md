# New task follows the active project, and a task can have no repo

New task now offers only the active project's repos (#225) on `agent/issues/225-new-connection-new-task`. Before, the form started on the first repo of any connection, so a new 'iml hub' project opened on a 'dxp' repo with 'dxp' work items, and the Repo list held every repo. `NewTaskScreen` takes `activeConnection` and lists the repos linked to it, plus repos linked to no project (as #219 does for tasks) and the repo a sprint row opened it with; the work item picker follows the chosen repo's connection as before.

The Repo list ends with No repo, and is the only choice when the project has no linked repos. Such a task has a name only and lives in a scratch folder, `<userData>/scratch/<slug>`, without git: setup makes the folder, writes `.shellie/task.md`, adds the brain's Context section, and opens the tabs. There is no branch, base, `.shellie.yml`, copy, setup command or secret, and it is always on Development. The project's brain (`brainForTask` by the task's connection and the connection's project) counts without a work item for such a task, so Claude gets `--add-dir <brain>` and the Brain tab shows. The task bar hides Docs, Changes, the branch, run entries, the environment chip and the repo menu; the nav lists these tasks under "No repo"; Finish is a short page that closes the terminals, can capture task.md into the brain and deletes the folder only when ticked; Discard deletes the folder; the Done page has no Reopen and main refuses one.

Stored format: `Task.repoId` is now nullable and `branch`/`baseRef` may be empty (only for a task without a repo). Every stored task has a repo id, so nothing migrates; an older Shellie would not read a store that holds a task without a repo. `CreateTaskInput` takes `repoId: null` and a `connectionId` for it.

Known gaps: a task without a repo has no git features and cannot become a repo task later; Docs is hidden since it lists files through git; a folder that cannot be deleted at Finish (Windows, a held file) stays and a notice says so, with no background retry. Not verified: in the running app, and on Windows. No telemetry change (`task.created` carries no repo data).
