# Brain: the Add view as one composer

Asked for: restructure Brain › Add, whose UX the owner found poor ("fields are too small, unfocussed. double fields"), designed in Claude Design to be "a top notch feature"; a Markdown editor decent enough to edit pasted input; binary files go in as they are with the note; the model for one add ("use opus for a big ppt deck"), for that add only. Spec: `docs/superpowers/specs/2026-11-10-brain-add-composer-design.md`; mockups on the Claude Design canvas https://claude.ai/artifact/HNagkGz94qedVqMRGP13Mu; plan: `docs/superpowers/plans/2026-11-10-brain-add-composer.md`.

The finished thing, a 1440 × 900 window: `assets/2026-11-10-brain-add-composer/composing.png` (text in Split view, two files, one with an Own note, the Opus hint), `dropping.png` (files dragged over the view), `after-add.png` (folded composer, Activity), `light.png` (light theme).

## What changed

- **One composer** (`composer/Composer.tsx`, `useComposer.ts`): a title (optional: the first heading, else the first line, cut at 60 characters), a Markdown editor, the attached files as chips, one "Note for the agent" for everything in the add, "Text goes in as", Capture with, Discard and one Add whose label counts what goes in ("Add text and 2 files"). A file gets its own note only through Own note on its chip; it then goes instead of the shared note. Partial failure: what went in leaves the composer and is reported, what failed stays with its problem line (named after its file). After an add that left nothing behind, the composer folds to one line until it is used again. The paste form, the per-file rows and their two Add buttons are gone from the Add view.
- **The editor** (`composer/MarkdownEditor.tsx`): Monaco in Markdown mode (lazy, as the Changes tab loads it; a plain text box until it has loaded, and for good when it cannot), a toolbar (heading, bold, italic, bullets, checklist, link, code, table, each one undo step), Write / Split / Preview (remembered per viewer; Preview is Read's `MarkdownView`), Ctrl or Cmd+Enter adds. Rich text pasted (`text/html`) is turned into GitHub-flavored Markdown with turndown and its GFM plugin (`composer/htmlToMarkdown.ts`, new dependencies `turndown` 7.2.4, `turndown-plugin-gfm` 1.0.2); "Paste as plain text" puts the plain text back for 10 s.
- **Dropping**: the whole Add view takes files; an overlay says how many and that Markdown and text open in the editor while other files attach as they are. The first `.md`, `.markdown` or `.txt` dropped on an empty editor opens in it (its name as title, type `doc`), every other file becomes a chip with its guessed type.
- **Capture with** (`composer/ModelPicker.tsx`, `jobs.ts`, `brainHandlers.ts`): the brain's model "(brain default)", or another for this add: Haiku, Sonnet, Opus on a Claude Code brain, `opencode models` on an OpenCode brain. `BrainJob.model` carries it; `brain:addText`, `brain:addFiles` and `brain:run` (capture only) take it; main refuses anything that is neither a Claude Code model nor a valid `provider/model`. A model for the other agent falls back to the brain's. Only the capture uses it: the lint after it, pictures, sync and every other job keep the brain's model; Retry and Capture all keep a failed capture's model. Once anything went in, the picker is back on the brain's model. With a deck or a file of 5 MB or more attached on a Claude Code brain not on Opus, a hint suggests Opus; it never switches by itself.
- **The draft** (`composer/draft.ts`, `draftStorage.ts`, store `brainDrafts`): per brain, kept while switching views and brains, and in local storage (debounced) so a reload or crash keeps typed text; the model is never restored. The task's Brain tab keeps its own drop list (`brainPending`, `PendingFiles`), unchanged and separate.
- **Activity** (`composer/Activity.tsx`, `activityRows.ts`): one card for Waiting to capture and Recent work. A source and its jobs are one row (its newest job stands for it); a job without a source is its own row; background jobs show while running or once failed. Groups Just added (queued, running, paused), Needs you (the Add badge's sources, a failed capture shown here only, with Retry; a file put in by hand with Capture; Capture all) and Earlier; filters All, Needs you, Running, Done. Rows keep today's actions (Retry, Continue in terminal, pages changed, Takeaways) and name the model when a capture had its own.
- **The rest**: How it works is the composer's `?` popover (the card and its Hide are gone); What runs by itself, Run now and Health are unchanged in behaviour, with quieter headings. `BrainInbox.tsx` is gone.
- **Telemetry**: `brain.screen.action` `add` gains counts and the model kind, and `paste-markdown`, `paste-plain`, `editor-view`, `discard` are new (`docs/telemetry.md`).

## Verified

`npm test` (all files green), `npm run typecheck`, `npm run lint`.

In the running dev app (`SHELLIE_USER_DATA=<scratch> npx electron-forge start -- --remote-debugging-port=<port>`, raw CDP), on a fresh data folder with a scaffolded brain and a fake `claude` first on the login shell's PATH that logs its arguments (no tokens spent): Monaco loads in the composer; an HTML paste with headings, a list, bold, a link, a table and a quote came out as the expected Markdown, Paste as plain text and then Undo worked step by step, Bold wrapped a Monaco selection; an add of text and two files with Opus ran both captures with `--model opus` and each lint after them with `--model sonnet`; a fake PDF was refused and stayed as a chip; the composer folded after a full add; the drop overlay, light theme and the Opus hint were looked at.

## Known gaps

- Dropping real files from Finder or Explorer was not done by hand; drops were simulated (a synthetic drop carries no file path, so chips were put in through the store).
- Not run on Windows or with an OpenCode brain live; the OpenCode model list and `-m` path are covered by unit tests only.
- The Monaco paths (toolbar edits, paste into Monaco) are checked in the app only; unit tests drive the text box fallback.
- The overlay lists no file names: Chromium does not give names while dragging.
- The editor's resize grip shows through the drop overlay.
