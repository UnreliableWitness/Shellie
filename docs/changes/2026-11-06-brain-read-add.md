# Brain: a Read view and an Add view

Spec `docs/superpowers/specs/2026-11-06-brain-read-add-design.md`, mockups in `docs/superpowers/specs/assets/2026-11-06-brain-read-add/`, plan `docs/superpowers/plans/2026-11-06-brain-read-add.md`. The owner found the Brain screen unusable for reading (the Inbox and Health cards filled the top, the wiki was one of three tabs under them, and opening a page replaced the list, so no tree stayed in view) and asked for help on the commands: how the brain works, what runs by itself and what does not.

## What changed

- **Header** (`BrainScreen`): the brain name, the project, then a **Read | Add** switch (`role="tablist"`). Add carries a badge with the sources waiting to capture (uncaptured, outside the DevOps wiki mirror, with no capture queued, running or paused by the token cap; `badgeCount` in `waiting.ts`), labelled "Add, N waiting". On the right the Ask box and a `⋯` menu with Open folder and Brain settings (Settings › Project › Brains). Refresh wiki, Lint, Digest and Open terminal leave the header for the Add view's Run now. The Sources, Wiki and Log tabs go.
- **Views**: both stay mounted and the inactive one is `hidden`, so the open page, the back/forward history and a half-filled paste form survive a switch. The view is remembered per brain in `localStorage` (`shellie.brain.view.<brainId>`, default Read); `focus: 'wiki'` opens Read, `focus: 'drop'` opens Add, `focus: 'ask'` keeps the view with Ask open. Each view fills the height under the header and scrolls on its own (Read per pane, Add as a whole); the brain terminal shows below the active view. The "last opened" timestamp behind the blue dots is read and moved once per Brain screen mount, so switching views does not clear the dots.
- **Read view** (`BrainRead`, `BrainTreeView`, `brainTree.ts`): a tree on the left (search on top, `⌘K`/`Ctrl+K` focuses it; Start here with the account, scope and latest digest pages and Recent changes; a collapsible group per page type with a count, collapsed state remembered per brain; Sources grouped by content type with the DevOps wiki mirror as a subgroup; Log at the bottom), blue dots on pages touched since the brain was last opened, the open page highlighted with its group expanded. The middle is the page at reading width; a landing of the pinned cards and Recent when nothing is open ("No pages yet. Add a source in Add." only once `brain:pages` has answered). The page's rail (`PageRail`): On this page, Linked from, Sources, Mark verified; it folds under the page header on a narrow window. Remove for a source moved into the page (`SourceBar`, hidden for mirror pages).
- **Add view** (`BrainAdd`): How it works (four steps, Hide remembered), Add to the brain (the drop zone and paste form; the whole view takes drops), Waiting to capture (why a row waits, only when an in-memory job says so: queued, capturing, failed with its error, paused by the token cap; else "not captured yet"; Capture per row and Capture all, a capture already queued, running or paused is not queued again), Recent work (a done capture links to the pages it changed, from its `log.md` entry), What runs by itself (`AutoRuns`, every line matching the code; the sync-after-refresh and weekly digest switches write the brain's options; the daily token cap with Resume), Run now (`RunNow`: Refresh wiki, Lint, Sync, Digest, Open terminal, each with a `?` from the new `HelpTip`), Health without the cost line.
- A link from Add (a capture's "N pages changed") switches to Read and opens the page, through `BrainRead`'s `openRequest` prop.
- `BrainFiles` (the old Sources tab) is gone, with its CSS.
- No text in the new views names an agent; no new IPC channels and no main-process changes. The task's Brain tab is unchanged.
- Telemetry: `brain.screen.action` gains `view-read`, `view-add`, `sync`, `help`, `option` (`docs/telemetry.md`).

## Verified

`npm test`, `npm run typecheck`, `npm run lint` green. Tests: `waiting.test.ts` (waiting sources, the reason per newest capture job, the badge with queued, running, paused and failed jobs), `brainTree.test.ts`, `recent.test.ts` (log entries keep their source, pages changed by a capture), `BrainRead.test.tsx` (tree, search, dots, Recent, Log, landing, `⌘K`, no empty-state before the pages answer), `BrainPage.test.tsx` (rail), `BrainAdd.test.tsx` (every section, the `?` texts, no agent names), `ui.test.tsx` (`HelpTip`), `BrainScreen.test.tsx` (opens on Read; `focus: 'drop'` opens on Add; the chosen view remembered across remounts; switching tracked; the badge at two and gone at zero; an open page kept across a switch; a pages-changed link opening Read on that page; `⋯` Open folder and Brain settings; no maintenance buttons in the header; pages, sources and the log loaded once for both views; `⌘K` from anywhere while Read is shown, not while Add is, not from another field). The Brain screen was rendered with sample data through a renderer harness (a fake preload API, Vite, headless Chromium) in light and dark; Read (tree, page, rail, landing) and Add (both columns) were looked at. That found the Add badge unreadable on the selected tab and the separators invisible (an undefined `--border`), both fixed. The full Electron app was not driven (the keychain prompt for safe storage).

## Known gaps

- "N pages changed" opens the first page only, not a short list of all of them.
- The mockup's "added outside Shellie" reason is not shown: jobs are not kept across restarts and nothing records where a source came from, so a row without a job says "not captured yet".
- OpenCode brains are a separate follow-up; the texts already avoid naming an agent.
- The blue dots and the remembered view, groups and How it works depend on `localStorage`.
