# Dependabot updates that merge and ship by themselves

Dependabot keeps the dependencies up to date (#193) on `issues/193-dependabot`. `.github/dependabot.yml` asks for weekly npm and GitHub Actions version updates (minor and patch grouped into one PR per ecosystem, majors one PR each, label `dependencies`, at most 5 open per ecosystem); security updates come as soon as an advisory is out once Dependabot alerts and security updates are switched on in Settings › Code security, which is done in GitHub, not in a file. The agents' PR poller (`tools/agents/pr.mjs`, `decideDependabot` and `dependabotUpdateType` in `pr-decide.mjs`) now also handles open PRs whose author login is exactly `dependabot[bot]` from a branch of this repo, without the LLM review or the fixer: in full mode it squash-merges a patch or minor update once the required checks and `main` are green, re-runs red CI once, leaves conflicts to Dependabot and updates a branch that is behind. A major or unknown update, a GitHub Actions bump (it touches `.github/workflows/`) and CI that stays red get `agent:awaits-owner` with one comment per commit; the owner's Approve on that commit lets the poller merge it, except past red CI. The owner-only rules for agent PRs are unchanged, so an agent PR that touches `package-lock.json` still waits. Runs of the PR workflow that Dependabot started (its CI finishing) are skipped because GitHub gives them no secrets; the 15-minute poll picks the PR up. Merged updates reach users through the scheduled release (12:00 and 17:00 Brussels) and the app's auto-update, which needed no change. Known gaps: not run live yet; merging an Actions bump with the App token may need the App's Workflows permission, so the owner may have to merge those by hand; the "force" part of the owner's "release and force auto update" is not done: the updater still shows its quiet Restart and update card (installing on the next start otherwise). No telemetry change.
