# The agents on a GitHub Project board

The agent flow now shows on, and can be steered from, the GitHub Project "Shellie" on the owner's account (2026-10-31, `UnreliableWitness/agents-project-board`). `agents-project.yml` runs `tools/agents/project.mjs` after every agent workflow and every 15 minutes: it creates the board the first time (linked to the repo, its Status field set to the agent columns Inbox, Needs info, Needs you, Ready, In progress, In review, Waiting for you, Merged, Released, Closed), adds every open issue (not the Agent activity issue), and moves each card to the column its labels say (`columnFor` in `project-columns.mjs`; the labels stay the source of truth). Steering from the board (`planSync` in `project-sync.mjs`): a draft card becomes an issue in the repo (created as the token's owner, so trusted, and triaged next); a "Needs you" card dragged to Ready becomes `agent:go` (`ownerIntent`); the order of the Ready column is the implementer's priority (`readyRank`, passed to `pickForImplement` as `rank`, before kind and age). A GitHub App cannot change a personal account's projects, so this uses the owner's classic token `AGENTS_PROJECT_TOKEN` (scopes `project`, `public_repo`), handed over in a file and used only in the sync and the pick, never where an agent runs; without it nothing is synced and the pick keeps its old order. Known gaps: GitHub sends no event for a moved card on a personal account's board, so moves are seen at the next poll; not run against the live API in this branch before the owner set the token.
