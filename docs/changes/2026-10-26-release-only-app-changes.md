# Releases only for app changes

A merge to `main` makes a new version only when something that goes into the app changed since the newest `vX.Y.Z` tag (2026-10-26, `UnreliableWitness/release-only-app-changes`). Before, every merge released, so changes to the agent pipeline, docs or tests (v1.63.0 only raised the agents' daily cap) became versions that every installed Shellie downloaded and announced in What's new. `tools/release/needs-release.mjs` decides: the agent pipeline (`.github/`, `.claude/`, `tools/agents/`), docs (`docs/`, root `*.md`), design, art sources (`tools/art/`, `assets/ART.md`, `assets/agents/`), tests and test helpers, dev tools (`tools/ado|telemetry|release/`, `tools/budget-check.mjs`) and lint and test config are not app files; anything else is, so a new kind of file errs towards releasing. CI's new `release-needed` job compares the newest release tag with `HEAD` (not the previous push, since a newer push can replace a waiting release run) and `windows-release` (and with it `macos-release`) runs only when it says so; tests still run on every push, and a `v*` tag pushed by hand always releases. The notifier closes an agent fix that touches no app files at once ("no new version") instead of reporting a missing release after 90 minutes.
