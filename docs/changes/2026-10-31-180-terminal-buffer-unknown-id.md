# A relaunch no longer reports "Unknown terminal" as an error

`terminals:buffer` now returns `null` for a terminal main does not know, instead of throwing "Unknown terminal <id>" (issue #180, 2026-10-31, `agent/issues/180-unknown-terminal`). After a relaunch (an update, for example) every open terminal tab asks main for its buffer; the new process has never started those terminals, so each one threw and the error reached Application Insights, although nothing was wrong: the renderer used that rejection as the sign that the terminal is gone. `TerminalManager.buffer` in `src/main/services/TerminalManager.ts` returns `null` for a missing id, and `TerminalView` treats `null` (or a failed call) as gone, so it shows "Process ended" and starts autoStart terminals again as before. `write`, `resize`, `kill` and the other calls still throw for unknown ids. The other callers (`TerminalFailures` in `src/main.ts`, the smoke test in `src/main/smoke.ts`) read `null` as an empty buffer. Telemetry events are unchanged.

Not verified: on Windows, where the report came from, and in the app itself (only through the unit and component tests). Not in this change: filtering errors in the telemetry layer, and how terminals restart after a relaunch.
