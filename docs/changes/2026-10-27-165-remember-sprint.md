# Sprint page remembers the picked sprint

The Sprint page now remembers the sprint last picked in its dropdown, per connection, across page switches and restarts (issue #165, 2026-10-27, `agent/issues/165-active-sprint-is-not-remembered`). Before, the choice lived only in the page's state, so going to another page and back showed the current sprint again and the user had to pick their sprint each time. The choice (sprint id and, with several teams, the team's name) is stored in `localStorage` under `shellie.ui.sprint.<connectionId>` by `writeSprintChoice` in `src/renderer/uiPrefs.ts` and read back with `readSprintChoice` when the page opens; unreadable data counts as no choice. When the remembered sprint is no longer in Azure DevOps, the page falls back to the current sprint as before and forgets the stored choice. This replaces "The choice is not remembered across restarts" in [the #143 note](2026-10-27-143-sprint-dropdown-all-teams.md).

Not verified: against a live Azure DevOps organization (only through the fake API in tests), and on Windows. Not in this change: syncing the choice between machines, the Home page sprints band and the work item picker's sprint scope, and how the default (current) sprint is chosen.
