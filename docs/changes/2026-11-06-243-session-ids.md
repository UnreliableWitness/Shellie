# Session ids in the Usage tab

Issue #243, branch `agent/issues/243-keep-track-of-opencode-sessions`. The Usage tab's Sessions table showed what each AI session cost, but not its id, so a lost terminal or session could not be continued with the same id.

## What changed

- The Sessions table in `UsagePanel.tsx` has a **Session** column. It shows the first 8 characters of the id in mono, with the full id in the tooltip, and a Copy button that writes the full id to the clipboard.
- For Claude Code and OpenCode the Copy button's tooltip also names the resume command: `claude --resume <id>` and `opencode --session <id>`. Copilot CLI rows show only the id.
- Rows with the `unknown-session` fallback id (Claude Code sent no `session.id`, see `otlp.ts`) show a dash and no button.
- No change to how ids are captured, to IPC, or to the CSV export, which already has a `session` column. The Lineage view is unchanged.

No telemetry changes.

## Verified

`npm test`, `npm run typecheck` and `npm run lint` are green. A new test in `UsagePanel.test.tsx` checks the shortened id, the copy of the full id, the resume command in the tooltip per tool, and the dash for `unknown-session`.

## Not verified

- Not checked in the running app, so the column's width in a narrow Usage tab is unseen.
- That `claude --resume <id>` and `opencode --session <id>` resume these exact ids was not tried by hand.
