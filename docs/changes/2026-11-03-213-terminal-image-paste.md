# Ctrl+V with an image on the clipboard reaches the program in the terminal

On Windows and Linux, Ctrl+V in a Shellie terminal now reaches the program as ^V when the clipboard holds no text (an image, say) or cannot be read (#213) on `agent/issues/213-ctrl-v-does-not-work-for-pasting-images`. Before, `attachClipboardKeys` in `src/renderer/terminalClipboard.ts` swallowed the key and pasted only text, so with an image on the clipboard nothing happened and opencode never saw the key it uses to read the image from the clipboard itself. Windows Terminal behaves the same way. Text pastes are unchanged and still go through xterm's bracketed paste. Ctrl+Shift+V and Cmd+V on macOS still never send ^V (Cmd+V sending ^V would trigger quoted-insert in zsh and bash; on macOS plain Ctrl+V already reaches the program). Known gaps: Shellie does not read or insert images itself; in bash, Ctrl+V with an empty clipboard now starts quoted-insert like in other terminals; not tried with opencode on Windows, only by unit tests. No telemetry change.
