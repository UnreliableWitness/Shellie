# Terminals and brain jobs start in a pty host, not in main

Terminals (node-pty) and the brain's headless `claude`/`opencode` jobs now start in a pty host: an Electron `utilityProcess` running the bundled `src/ptyHost.ts` (issue #271, 2026-11-12, `agent/issues/271-main-process-event-loop-stalls-of-5-s-an`). On Windows, ConPTY's `connect` and libuv's `spawn` both call `CreateProcessW` synchronously, and the owner's stall profiles showed that taking 1.1 to 1.5 s per terminal and 1.2 s per brain job (probably on-access scanning of a large executable, not proven). Main was blocked all that time, and so were every IPC call and the UI. Now that wait blocks the host.

How it works:

- `src/main/ptyHost/protocol.ts` has the messages. Main sends `spawn`, `write`, `resize`, `kill` and `run`. The host sends back `spawned` (with the pid), `spawnError`, `data`, `exit`, `ran` and `runError`. Each spawn or run has its own number, because a restart reuses the terminal id while the old process may still be exiting.
- `src/main/ptyHost/host.ts` does the host's side. It calls `pty.spawn`, still with `useConptyDll: true` on Windows, and runs jobs through `runWithInput`.
- `src/main/ptyHost/client.ts` (`PtyHostClient`) is main's side. It starts the host the first time it is needed (`src/main/ptyHost/utility.ts`) and relays to it. Its `run` gives the same results and errors as `runWithInput` (an `ExitError` for a non-zero exit, with the `code` kept, so the brain's "OpenCode was not found" still works).
- `TerminalManager` takes the host in its constructor and no longer imports node-pty. `spawn` and `restart` now return a promise that rejects when the host could not start the process. The terminal is known as soon as `spawn` returns, so the task claims are still held for no tick. The handlers await the promise after the claim and record the spawn failure as before. Exit codes, `UNKNOWN_EXIT`, the remembered size and output that arrives after the exit behave as before.
- If the host crashes, every terminal it held is marked exited with `UNKNOWN_EXIT`, pending spawns and brain jobs fail with "The terminal host stopped", and the next spawn or job starts a new host.
- `forge.config.mts` builds `src/ptyHost.ts` as a third main-target entry (`ptyHost.cjs`). node-pty stays external and unpacked. The packaged smoke check (`SHELLIE_SMOKE=1`) now spawns its pty through the host.
- In the tests, `src/main/test-helpers/ptyHost.ts` runs the host in-process with real node-pty, with every message delivered asynchronously.

No telemetry events changed. When the host exits, main logs `[terminals] the terminal host exited (<code>)`.

Not done: the git concurrency cap for `review:count` and `tasks:gitSummary` polling (about 100 ms of main per `git` spawn on that machine) is left for a follow-up. The PR summary at Finish and the PDF rasteriser still start their processes from main. The two idle-only stalls, the unexplained 89.9 s gap, `Update.exe` (#261) and the OpenCode scan (#262) are not addressed.

Not verified: the packaged app on Windows (whether the stalls are gone, ConPTY in the utility process, and conpty.dll loading from there), and the packaged app on macOS and Linux. It was checked only through the unit tests on macOS, plus Windows CI.
