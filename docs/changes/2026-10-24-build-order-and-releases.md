# Build order

Build order (releases carry a macOS build too since 2026-10-24, see the macOS release entry): (1) app shell and task lifecycle, done; (2) Azure DevOps integration, done (read-only: connections, picker, header link); (3) usage capture and pricing, done (Claude Code via OTLP receiver on 127.0.0.1:4319, Copilot CLI via per-task file, official-price rate table, EUR, work item write-back since removed: writing cost to Azure DevOps (the `Custom.AI*` fields, the usage comment, the hourly sync, the PR cost line, setting `writeCostToAdo`) was opt-in from 2026-10-16 (#35) and was removed on 2026-10-23 for the cost ledger below); (4) official prices only, done: all amounts use the built-in official rate table and USD to EUR 0.92, no local rates or markup, so every teammate prices identically. Invoicing is management's decision, made on the cost server's data. Reconciliation against Anthropic and GitHub billing is deferred to a later sub-project. (5) Windows support, done (PR #5); (6) sci-fi UX, splash, icon and art, done, its look since replaced by the ADO redesign (#9 #10 #11 #12 #15). (7) auto-update, merged (PR #16, issue #13): packaged Windows and macOS builds update (macOS from /Applications only, see `docs/macos-release.md`); Windows uses Electron's `autoUpdater` (Squirrel.Windows) with the update.electronjs.org feed, in `src/main/autoUpdate.ts` (no check on `--squirrel-firstrun`, first check after 30 s, then every 10 minutes (#126, below); a downloaded update shows a quiet card in the notice corner (no dialog) with Restart and update / Later, also in a window opened after the download (`update:status`, `update:ready`, `update:install`); Later installs on the next start; `"autoUpdate": false` in `settings.json` turns it off, no UI yet). Every push to `main` (each merged PR, #36) releases the next minor version: `tools/release/next-version.mjs` takes the highest `vX.Y.Z` tag on the remote, bumps the minor and resets the patch, the build carries that version, and `gh release create --target <sha>` makes the tag (one release job at a time, `concurrency: windows-release`). A `vX.Y.Z` tag pushed by hand still releases exactly that version. Each release is a normal (not pre-) release with `Shellie-Setup.exe`, `RELEASES` and the `.nupkg`, signed or unsigned. Next: winget distribution (manifest in microsoft/winget-pkgs pointing at the GitHub Release installer, best after signing is live) and Squirrel delta updates. Faster updates and What's new (#126, 2026-10-23, `issues/126-updater`): the checks used to stop for good at the first downloaded update (by design then), so an app left open after Later never saw the releases after it, and with a release per merge it lagged several versions behind; now checks go on after a download (Squirrel downloads the newer package too, `update:ready` fires again and the card shows again after Later), run every 10 minutes (update.electronjs.org's documented interval; its `CACHE_TTL` holds a repo's latest release for 15 minutes, so a release reaches an open app within about 25), check on `resume` and `unlock-screen` (at most once per 5 minutes), never start while a check or download runs, and treat a check without a result for 30 minutes as lost so a missed event or a hung Update.exe cannot stop them. Release notes: the GitHub Release body (`--generate-notes`, the merged PRs) is the long version; after an update Home shows a What's new card (`WhatsNewBand`, `app:whatsNew`, `src/main/releaseNotes.ts`) with the PR titles of every release since the last dismissed one (setting `whatsNewSeen`), read once per launch from the public GitHub Releases API (not bundled, since one update can skip several releases), a Release notes on GitHub link and Dismiss; offline it shows only the link; a fresh install records its version so it gets no card, an install from before this shows the running version's notes once; packaged builds only.
